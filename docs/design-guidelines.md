# Netariumデザインガイドライン

NetariumのUI設計、画面操作の文言、色彩、アイコン資産の取り扱いにおける判断基準を定める。機能追加や画面改修において、視認性と操作の一貫性を保ち、利用者が迷わずに操作できる状態を維持することを目的とする。

## 設計の基本方針

ネットワーク管理業務では、多くの数値や設定項目を迅速に読み取り、誤認なく操作することが求められる。この要求を満たすため、Netariumの画面設計では次の4原則を優先する。

### 視覚表現と役割の一致

UI要素の視覚的表現は、画面上の役割と一対一で対応させる。特定の要素を目立たせたいという理由だけで定義から外れた色や装飾を適用すれば、操作可能なボタンと単なる状態表示の境界が曖昧になり、誤操作を誘発するためである。利用者が画面を見た際、どの要素が操作可能で、どの要素が状態を示しているかを即座に判別できる状態を保つ。

### 操作動線の分離と複雑さの抑制

高機能であることと、画面操作が煩雑であることは同義ではない。すべての設定項目を単一の表示領域に並べれば利用者の認知負荷が増大するため、日常的に参照・更新する項目を主動線に配置し、低頻度の高度な設定や破壊的な操作は、モーダルダイアログやプロパティパネルの下層に配置して操作の動線を分離する。

### 業務利用における描画の安定と余白設計

自治体や公共機関などの公務・業務利用を想定し、落ち着いた階調と標準的な余白設計を採用する。視覚効果や過度なアニメーションを排し、安定した描画速度と読みやすさを優先する。

### 複数要素による状態識別

状態や種類の区別を色彩のみに依存させない。色彩の変化に加えて、形状、アイコン、ラベル文字列、境界線の種類を併用し、多様な表示環境や色覚特性においても判別可能な情報設計とする。
## 画面要素と情報階層

限られた画面領域の中で必要な情報を見落とさないよう、画面要素の配置と情報階層を統一する。

<a id="ヘッダー検索候補と補助操作163"></a>

### ヘッダー・検索候補と補助操作

ヘッダーの検索欄は伸縮させ、ダッシュボードから管理・利用者メニューまでの操作群は右側へまとめる。1150px以下では操作ラベルを省略し、640px以下では検索を上段、操作群を右寄せの下段へ配置する。検索候補はヘッダーボタンの固定高さ・中央配置を継承せず、44px以上の操作領域と内容に応じた高さで左揃えにする。名称14px・補足12pxを基準に、長い名称・設置情報は折り返す。機器候補の横幅は最大380pxに抑える。候補の強調はPrimaryとし、機器検索・ビュー内一覧の接続検索・機器台帳検索のfocus-visibleは共通`base.css`でPrimaryの2px枠と2pxの間隔へ統一し、黄色の影を除去する。それ以外の操作はDADS表示（内側の黄色2px＋外側の黒4px）を維持する。

ダッシュボードの更新は右上×の左へ文字付きの補助ボタンとして配置し、閉じる操作と区別する。接続系統の単一選択は右パネル・一括設定で色の丸＋名称を共用し、選択はチェックと読み上げ状態でも示す。個票ヘッダーは機器名と閉鎖操作に絞り、識別ID・種別・IPアドレスは本文の基本情報に残す。下部中央の注意通知は複数行も左揃えにする。

CSV取込仕様は折り畳まず常時表示する。通常幅は5分類を3列・2段にまとめ、1000px以下は2列、760px以下は1列へ切り替える。ファイル選択・仕様・実行操作を見渡せるよう余白を抑え、検証結果の表は残りの高さに合わせて内部をスクロールさせる。狭幅・低い画面・拡大表示ではモーダル本文のスクロールも許容し、説明や操作を隠さない。


### キャンバス上の機器ノード表示

構成図上の機器ノードは、機器名とIPアドレスの表示階層を明確に分ける。

- 機器名は主情報として扱い、標準フォントサイズで明瞭に表示する。
- IPアドレスは補助情報として扱い、機器名より一段小さいフォントサイズかつ中立的な二次テキスト色で表示する。
- 機器ノードの横幅は、標準的なIPv4アドレス（最大15文字）が見切れずに表示できる幅を確保する。
- IPアドレスは状態を示す値ではないため、PrimaryやWarningなどの状態色を付与しない。

実装の基準寸法はワールド座標で幅108px。通常幅では機器名14px・太字、IP11px・通常字・`--text-muted`とし、長い機器名はellipsisで省略する。CSSトークンとJavaScriptの共有寸法を揃え、配置ゴースト・接続経路・全体表示・印刷でも同じ幅を使う。狭幅の既存文字サイズとCanvas倍率による縮小は維持する。

左の配置・一覧・接続補助パネルは304pxを基準に、`calc(100vw - 72px)`以下へ制限する。パネルはCanvasに重ねて表示し、開閉だけではCanvasやフッターの位置・倍率を変えない。配置パネル見出しは16pxで接続パネルと揃える。空の配置待ちは「下の候補から選択してください」、候補の追加は「配置待ちに追加」、キュー内機器の削除ボタンは「×」で統一する。ビュー内一覧の機器行・接続行はボックス外形（高さ39px、padding 4px 6px、radius 2px）と文字サイズ階層（上段12px太字、下段10px neutral gray）を統一する。機器行は上段に機器名、下段に種別とIPアドレスを表示し（Pingステータスは非表示）、接続行は上段に端点機器名、下段に系統スウォッチ（10px）＋系統名およびラベルのみを表示する（VLANとポートは非表示）。接続タブの一括操作は「選択解除」「一括設定」を横並びとし、下段に「すべて選択」を配置する。

<a id="ping状態の表示157"></a>

### Ping状態の表示

Canvas・台帳・個票・右パネルの基本ラベルは「OK」「NG」「未確認」、実行中は「確認中」とする。「未確認」の「？」や「－」への短縮は採用しない。台帳のOK／NGには補助記号を残すが、色だけで状態を区別しない。実行結果のタイムアウト・スキップは原因の分類であり、NG・未確認へ表示を一括置換しない。

Canvasはノード外枠と状態ラベルに共通のSuccess／Danger／Unknown／Infoを使い、アイコン枠は中立色にする。選択の青い背景・外側破線と接続元のラベル・外側強調は、Ping状態の外枠を上書きしない。確認中の点滅は`prefers-reduced-motion`で停止する。

応答時間・最終確認日時・エラー全文はCanvasと一覧のtooltip・読み上げ名で確認できる。確認中の説明には以前の応答時間・エラーを含めない。一覧は2段表示を維持し、状態をtooltipと読み上げ名だけに補う。台帳の監視詳細、個票・右パネルの詳細、フッターからの実行結果への導線は維持する。


### 入力フォームと文字数管理

入力フォームにおける文字数の制限と案内は、入力欄の用途に応じて制御する。

- 単一行入力欄（機器名、ラベル、ポート番号、VLANなど）では、常時の文字数カウンタ表示（例: `0/50`）を行わない。文字数上限の検証は維持し、超過時は入力欄近傍へ理由を表示する。`maxlength`で無言に入力を遮断せず、超過値を保持して確定前に修正できるようにする。機器・接続・ビューはUnicodeコードポイントで検証する。認証パスワードの既存バイト制限は文字数と混同せず、条件を明記する。
- 長文入力用のテキストエリア（備考や詳細説明など）に限り、入力文字数カウンタの常時表示を認める。文章全体の構成を確認しながら入力する作業を支援するためである。
- 機器種別は台帳・個票・右パネルで共通の単一選択ピッカーを使い、選択中の値と候補の両方にアイコン＋種別名を表示する。キーボード操作・ariaの選択状態・モーダル内フォーカスを維持し、Escは候補の閉鎖を先に行う。

<a id="認証アカウント画面156"></a>

### 認証・アカウント画面

login/setupは`public/assets/backgrounds/auth-network.svg`を共用する。左右の点・線と少数の4色ノードは装飾であり、通信状態や操作対象を表さない。背景は白に近い淡色の静的・ローカル配信とし、正式ロゴを別要素で維持する。中央の余白、不透明なフォームカード、狭幅で背景を薄くする指定により入力を主情報として扱う。背景未読込時は単色、長いフォーム・拡大表示ではページスクロールで入力と主操作を隠さない。

登録（初期パスワード）・変更・setupは共通条件部品を使い、新規設定の12～128文字（Unicodeコードポイント）・UTF-8最大512バイトを案内する。文字種混在は強制せず、コードポイントと見た目の文字の違い、空白保持、正規化なしの詳細は利用ガイド（ヘルプ）と管理者ガイドで補完する。NUL・不正Unicode、512バイト超、128文字超、12文字未満、確認不一致の順でPHP／JSのエラーを一致させる。超過値を遮断・切り捨てず保持する。ログイン・現在値の照合に新規条件を適用しない。利用者登録のユーザー名ヒント（3～50文字）と登録済み一覧の再設定条件は常設せず、再設定も共通の判定と近傍エラーを使う。変更の再ログイン注意は実行ボタン直前に一度だけ表示する。利用者管理の常設説明・一覧更新成功通知・セッション失効のフッター説明は表示せず、再設定の実行確認で失効を伝える。登録済み利用者の操作は適用・再設定入力・再設定の横一列とし、共通`btn btn-sm`（高さ36px・角丸4px）のPrimary／Secondaryで揃える。狭幅では表の横スクロールを維持し、近傍エラーは操作行の下へ表示する。

## 操作語彙ルール

同じ意味の操作には同じ用語を用い、異なる意味の操作には別の用語を割り当てる。似た意味の言葉を画面ごとに使い分けることを禁止する。

| 操作用語 | 定義と役割 | 適用例 |
|---|---|---|
| **適用** | 入力中の値を確定し、自動保存キューへ送る操作。画面上部の「保存」を別途押下する必要はない。 | 機器個票の編集確定、右プロパティの入力確定、表示スタイルの確定 |
| **完了** | 特定の編集モードや調整モードそのものを終了する操作。永続化の実行を意味させない。 | 経路調整モードの終了、図面調整モードの終了、メモ編集モードの終了 |
| **保存** | 確定済みの変更を明示的に永続化する操作。Netariumでは通常操作は自動保存されるため、未送信データの強制送信や再試行などの特殊な用途に限定する。 | 上部ツールバーの保存（未送信キューの即時フラッシュ、再試行） |
| **登録** | 新しい実体やレコードを新規作成する操作。既存実体の変更・更新には使用しない。 | 新規機器の作成、フロア図面の新規追加、新規利用者の作成 |
| **削除** | 対象の実体を除去する操作。影響が大きい場合は「機器を完全削除」「フロア図面を削除」のように対象を明示する。「確定」「実行」といった抽象的な言葉で代用しない。 | 機器の削除、ビューの削除、接続の削除 |
| **キャンセル** | まだ確定していないダイアログや入力フローを、破棄して閉じる操作。 | 編集ダイアログの中止、モーダルの破棄 |
| **変更を取り消す** | 画面上で実施した変更を、操作開始時点または前回確定済みの状態へ戻す操作。単なるダイアログ破棄（キャンセル）と区別する。 | 右パネルの未適用入力を前回適用した値へ戻す |
| **戻る** | 複数ステップで構成される作業フローにおいて、直前の画面へ1段階戻る操作。入力内容は保持する。 | 取込ウィザードの前ステップへの移動 |
| **閉じる** | 編集内容の破棄を伴わない、閲覧中心のダイアログやヘルプ画面を閉じる操作。 | 操作ヘルプ画面、ダッシュボード、情報通知 |

title・aria-label・tooltip・確認・トースト・状態表示・ヘルプも同じ語彙に揃える。台帳・個票は未適用入力がある時は「適用」、確定済み変更の送信・再試行だけを行う時は「保存」と表示する。危険な操作には「取込を実行」「復元を実行」のように対象と動作を明記し、「OK」「確定」「実行」だけを使わない。

機器間の関係は「接続」に統一し、接続情報・接続一覧・接続モード・接続系統・接続ラベル・接続経路と表記する。「経路」だけで通じる箇所は長文化しない。物理ケーブル実体には「配線」「ケーブル」を使用でき、Webページのハイパーリンクも「リンク」のままとする。内部のDB・API・変数・module・migrationの`link`命名と、過去Issue・変更履歴は表示文言のために改名・改稿しない。

### モーダルの閉鎖

閲覧画面は原則として右上の×を使い、背景クリック・Escでも閉じられるようにする。未確定編集がある画面は、×・背景・Esc・キャンセルを同じ閉鎖判定へ渡し、入力が失われる場合は確認するか、処理中の閉鎖を抑止する。確定済みの自動保存変更は巻き戻さない。「キャンセル」は未確定フローの中止、「変更を取り消す」は編集結果の復元に限る。

×は`modal-close-btn`と共通neutral tokenを使い、32px以上の操作領域、hover・focus-visible・disabled、`type="button"`、`aria-label="閉じる"`を統一する。閲覧画面の冗長な「閉じる」フッターは設けず、適用・登録・必要なキャンセルは残す。閉鎖条件と対象分類は[アーキテクチャ](architecture.md#モーダルの閉鎖とフォーカス153)を参照する。

キャンセルは`btn-cancel`を使い、Secondaryと同じNeutralの文字色・背景・枠線にする。一括編集と接続系統設定の操作ボタンは高さ32px・同じ文字サイズ・上下余白に揃え、キャンセルを主操作の左に置く。印刷は右寄せでキャンセル・印刷を隣接させる。管理接続の「ブラウザで開く」「SSHで開く」はPrimaryの青色とする。

## ボタン階層

1つの画面領域の中に複数の主ボタンが並ぶと、利用者の判断が滞る。ボタンの役割と重要度に応じて4段階の階層を使い分ける。

```text
Primary（主操作）
  └─ 1画面・1領域に原則1つ。画面の主要な前進操作（適用、登録、次へ、実行）
Secondary（補助操作）
  └─ 通常の補助的な操作（キャンセル、戻る、完了、全体表示）
Tertiary（低頻度操作）
  └─ 補助的なリンク、詳細表示、ヘルプ呼び出し
Danger（破壊的操作）
  └─ 削除、破棄、不可逆な変更。Primaryとは明確に区別し、赤系で警告する
```

「重要だから赤」「目立たせたいから青」といった主観的な配色を禁止する。破壊操作のみにDangerを割り当て、主要操作にはPrimaryを割り当てる。

実装は`base.css`の`btn`と役割別クラスを共用する。SecondaryはNeutralの枠付き補助操作、TertiaryはPrimaryの文字・下線、Dangerは赤系とし、hoverでも同じ意味を維持する。削除などを控えめに示す場合は`btn-danger btn-secondary`を使う。共通フッターと未適用確認は寸法・配置だけを調整し、役割別の色・hover・disabledを専用CSSで上書きしない。

なお、「完了」ボタンは原則として補助操作（Secondary）に位置づけるが、キャンバスコンテキストツールバーのように、モード終了がその操作領域における唯一の主要アクションとなる文脈ではPrimaryとしての配置を認める。
## セマンティックカラー規律

色彩は個人の好みではなく、状態や機能の意味に結びつけて定義する。新規画面やスタイル改修では画面固有の直接カラーコード記述を避け、定義済みの共通デザイントークン（`tokens.css`）を優先して使用する。既存の画面スタイルに残存する直接指定は、再利用性とセマンティックな意味を確認しながら段階的に共通トークンへ置き換える。

| 色系統 | 役割と用途 | 誤用防止の規律 |
|---|---|---|
| **Primary / Info**（青系） | 主操作ボタン、ナビゲーションのアクティブ項目、情報の通知、フォーカス選択状態。 | 単に目立たせたいだけの装飾に使用しない。 |
| **Neutral**（白・グレー系） | 補助操作ボタン、中立的なテキスト、境界線、背景。 | 重要なアクションを曖昧にする目的で使用しない。 |
| **Danger**（赤系） | 削除ボタン、重大なエラー、競合状態、回復不能な警告。 | 重要ではあっても破壊的でない通常操作に赤色を割り当てない。 |
| **Warning**（黄〜アンバー系） | 注意喚起、未確定状態、保存待ち、接続条件の不足。 | 「選択中」「現在作業中」を目立たせるために警告色を使用しない。配線モードにおける接続元機器の選択状態にはPrimaryを使用する。 |
| **Success**（緑系） | 処理完了の通知、疎通確認の成功状態、正常稼働状態。 | 「保存ボタン」などのアクションボタンを装飾する目的で緑色を使用しない。 |
| **Unknown / Disabled**（グレー系） | 未確認状態、無効化された操作要素。 | 操作可能な要素を無効に見せかける配色を避ける。 |

## アイコンとブランド資産の規律

視認性を維持し、画面の読み込み負荷を低減するため、アイコン資産の取り扱い方針を統一する。

### ベクター資産の原則

画面表示に使用する正式なUI資産は、SVG形式に限定する。PNGなどのラスター画像は、デザイン原案や確認用のリファレンスとしてのみ保持し、本番の画面実装にラスター画像を配置したり、SVG内部へ埋め込んだりしない。

### ディレクトリ構造と責務

アイコン資産は `public/assets/icons/` 配下で次の4ディレクトリに分類して管理する。

```text
public/assets/icons/
├─ brand/     Netarium自体のロゴ、サービスマーク、ファビコン
├─ devices/   構成図キャンバス上で使用するネットワーク機器アイコン（8種類）
├─ toolbar/   作業パレットやツールバーの操作ボタン用アイコン
└─ app/       ダッシュボード、台帳、管理などシステム共通機能用アイコン
```

各カテゴリの境界を維持し、同じアイコンを別ディレクトリに重複して配置しない。

### 小サイズ表示への最適化

アイコンのSVGデータを作成・改修する際は、次の規律を遵守する。

- 縮小表示した際に輪郭が潰れないよう、余分なパスや微細なアンカーポイントを排除する。
- ドロップシャドウ、グロー、複雑な多段グラデーションをSVG内部に直接記述しない。陰影が必要な場合はCSSで制御する。
- 16px〜32pxなどの極小領域で使用するアイコン（ファビコン等）は、通常サイズの単純縮小ではなく、線幅や要素の間隔を広げた専用のCompact資産を用意する。
- アイコン単独で配置する操作ボタンには、必ず `aria-label` または `title` 属性を付与し、音声読み上げやキーボード操作におけるアクセシビリティを確保する。

# Netariumアーキテクチャ

## 目的と前提

Netariumは、イントラネット内のネットワーク機器、配置、接続関係、フロア図面を一元管理するIIS向けWebアプリケーションです。外部サービスやインターネット接続を実行時の前提にしません。

この文書を現在の構造・データ契約・処理境界の正本とします。開発と検証の手順は[開発ガイド](development.md)を参照してください。配備の操作手順は[配備ガイド](deployment.md)、更新は[更新ガイド](update.md)、復旧・撤去は[運用ガイド](operations.md)を正本とし、この文書の構成図を手順の代用にしません。

## 公開領域と実行時領域

IISのDocumentRootは`public/`です。リポジトリルートを直接公開しません。

```text
Browser
  └─ public/
       ├─ index.php          画面
       ├─ api.php            APIフロントコントローラー
       ├─ image_upload.php   画像登録専用フロントコントローラー
       ├─ login.php          ログイン
       ├─ setup.php          初期管理者設定
       ├─ floor_plan.php     認証付き図面配信
       ├─ device_image.php   認証付き機器画像配信
       ├─ js/ css/ assets/   静的ファイル
       └─ web.config         公開領域のIIS規則
              │
              ▼
bootstrap.php
  ├─ src/Autoloader.php
  ├─ src/Services/Auth/      認証・セッションの共通関数
  ├─ src/Core/Database.php   接続・設定・初期化
  ├─ src/Core/DatabaseSchema.php スキーマ11・移行・初期ビュー
  └─ src/Core、Actions、Services、Repositories

templates/                   Web非公開テンプレート
resources/password-blocklist/ Web非公開の拒否データ・出所／ライセンス
config/app.php               環境固有設定（Web非公開、Git管理外）
data/                        実行時データ（Web非公開）
  ├─ db/data.sqlite
  ├─ uploads/floorplans
  ├─ uploads/device_images
  ├─ backups/auto
  ├─ logs
  │    ├─ audit
  │    └─ restore.log
  └─ temp
```

`Config`が実行時パスを一元化します。`NETARIUM_STORAGE_DIR`が設定されていればそれを優先し、次に`config/app.php`の`storage_dir`、最後にインストールルート直下の`data/`を使用します。DBは`NETARIUM_DB_FILE`、`config/app.php`の`db_file`、`<storage_dir>/db/data.sqlite`の順で選択します。`db_file`は設定したローカル`storage_dir`配下に限定します。

`floor_plan.php`と`device_image.php`は認証を確認したうえで画像を配信します。`data/uploads/floorplans`と`data/uploads/device_images`をIISの静的ファイルとして公開しません。

## リクエストの流れ

`public/api.php`と`public/image_upload.php`は`src/Core/ApiDispatcher.php`を呼び出します。共通ディスパッチャーがセッション、CSRF、認証・認可、ルーティング、監査、操作ロック、例外ハンドリングを担当します。画像専用入口は図面・機器画像の登録actionだけを受け付け、旧`api.php`ではこの2actionを受け付けません。画像入口のIIS要求上限はmultipart込み31MiB、ZIP復元を含む通常入口のSite上限は32MiBです。

図面の入力契約（30MiB・各辺7,000px・3,500万画素）と保存契約（同形式・長辺4,096px・10MiB以下）を分離します。GDでEXIF向きを補正して縮小・再エンコードし、PNG透過を保持して小画像を拡大しません。原本はPHPの一時ファイルのみで、保存容量とDBメタデータは変換後の実バイト数・寸法・MIME・SHA-256を使います。競合時は旧図面を保全し、中間ファイルを片付けます。画像登録の全体一律上限（108ファイル／200MiB）は撤去し、ディスク空き容量および任意の運用クォータで管理します。PHP推奨設定は`upload_max_filesize=32M`／`post_max_size=34M`、IIS Site通常要求は32MiBとします。Web ZIPの24MiB／展開後64MiB／2ファイル契約とは独立です。図面変換は[アーキテクチャ](architecture.md)、Web ZIPは[運用ガイド（復元）](operations.md#復元)を参照してください。

- `src/Services/Auth/Session.php`: セッション開始・期限・破棄、CSRF
- `src/Services/Auth/Authentication.php`: ログイン、利用者状態・世代の再確認、認証用DB取得
- `src/Services/Auth/LoginRateLimit.php`: DBに保存するログイン試行制限
- `src/Services/Auth/CredentialValidation.php`: ユーザー名・新規パスワードの共通検証
- `src/Services/Auth/PasswordBlocklist.php`: オフライン全体照合・文脈／反復拒否、データ異常時の設定拒否
- `src/Services/Auth/ReauthenticationLimit.php`: 利用者単位の現在値照合制限（呼出元のwriter transaction内）
- `src/Services/Auth/PasswordSprayDetector.php`: 接続元別の横断失敗集計・警告、期間／保存件数の清掃
- `src/Services/Auth/HttpAccess.php`: HTTP要求の認証・権限検査、応答。CSRF検査はSessionに置く
- `src/Core/Database.php`: `connect`でPDO生成と共通初期化、`configure`で接続設定、`initialize`で設定・スキーマ移行・初期ビュー生成、`open`でAPI用保存先検証後の接続取得
- `src/Core/DatabaseSchema.php`: `APP_DATABASE_SCHEMA_VERSION = 11`、画像の`sha256`列追加を含む移行関数と初期ビュー生成。ドメインのCRUDは移さない
- `src/Core/`: Request、Response、Database、DatabaseSchema、ApiException、Config、AuditLog、ApiDispatcher
- `src/Actions/`: ActionInterfaceを実装したエンドポイント
- `src/Services/`: Auth、Topology、Monitoring、Csv、Backup、FloorPlan、DeviceImage、Storage、Quality
- `src/Repositories/`: Device、View、Placement、Link、FloorPlan、AppMetaなどの永続化

`bootstrap.php`はCLIとWebの共通入口です。オートローダー登録後にDatabaseとスキーマ定義を読み、`Config`から`APP_DB_FILE`を定義してAuthの共通関数群を読み込みます。この時点ではDBへ接続しません。クラスは既存オートローダー、グローバル関数は明示的な読み込みを使い、認証・移行の既存関数名を保持します。認証用DBの保存先検証は認証側に残し、PDO生成・接続設定は`Database::connect`を共用します。ルートの`auth.php`・`database.php`と互換shimは残しません。公開PHPと管理用CLIはbootstrap、隔離DBを用意するテスト用サーバーとbenchmarkはDatabaseを直接読み込みます。Serviceがドメイン操作とトランザクションを制御し、Repositoryが問い合わせを担当する境界は変更しません。

## データモデル

| テーブル | 役割 |
|---|---|
| `users` | ユーザー、パスワードハッシュ、権限、認証世代、`must_change_password` |
| `login_rate_limits` | ユーザー名単位の失敗・照合中の予約回数と一時ロック |
| `reauthentication_limits` | 利用者ID単位の本人変更時の再認証制限 |
| `password_spray_failures`／`password_spray_warnings` | 接続元・対象のdigestによる有界失敗集計と警告間隔 |
| `views` | 論理構成図またはフロア配置図、ビュー単位の`resource_revision` |
| `devices` | 機器台帳の正本、機器単位の`resource_revision` |
| `device_placements` | ビューごとの機器配置座標 |
| `links` | ビュー内の機器間接続 |
| `device_monitor_status` | 手動Pingの最新結果 |
| `view_floor_plans` | フロア図面のメタデータと表示設定 |
| `device_images` | 機器画像のメタデータと表示順 |
| `app_meta` | データリビジョン、監視リビジョン、更新日時 |
| `resource_sequences` | ID・リソース世代の単調カウンター（バックアップの復元対象外） |

機器情報と配置情報は分離されています。同じ機器を複数のビューへ配置できます。リンクはビューに属し、接続対象となる機器を参照します。

業務リソースIDの共通上限は`Core/ResourceId::MAX`（9,007,199,254,740,991）です。API・CSVでは整数のキャスト前に検証し、通常のサーバー採番はこの上限まで発行します。ZIP復元と全体保存の新規明示IDは、次の1件分を残す`MAX_RESTORE`（9,007,199,254,740,990）以下に制限します。既存行の最終IDの更新は維持します。リソースIDと世代番号（`resource_revision`）の検証は分離し、世代番号にはID上限を適用しません。クライアント側（`state.js`）の仮ID採番は現存IDが上限付近にあっても安全な正の整数範囲の未使用値を割り当て、最終ID発行後の新規登録要求でも安全な仮IDからサーバー側の409枯渇判定へ到達させます。復元は現行の6種類のIDカウンター、機器画像の`sqlite_sequence`、現存各表の最大IDも検査し、確定時はwriter lock取得後に再検査します。通常採番の枯渇は409（`details.reason = 'id_exhausted'`）、復元の採番余地不足は400で拒否し、トランザクション内の変更を残しません。クライアント（`save-queue.js`）はID枯渇409を楽観ロック競合と区別して保存エラーとして扱い、未競合のリソースが再読込・破棄フローに巻き込まれるのを防ぎます。現行DBスキーマ11・Web構成情報ZIP（`netarium-config`形式1）でもID採番上限と既存の非再利用トリガーの仕様を維持しています。

DBスキーマ7の`links.route_mode`は`auto`または`manual`、`manual_route`は中間点`[{x, y}, ...]`をJSONで保持するTEXT列です。機器中心・始点・終点は保存しません。load・保存応答・バックアップではJSON文字列ではなく配列へ変換し、旧リンクは`auto`と空配列になります。新規リンクの通常UIも`auto`で作成します。

`Topology/LinkRoute.php`はAPI・バックアップの共通検証を担当します。中間点は最大8点、各点は有限数の`x`と`y`だけを持ち、隣接点は水平または垂直とします。`auto`では空配列だけを受け付けます。座標の符号や大きさには追加の制約を設けません。最大点数の正本は`LinkRoute::MAX_POINTS`で、`APP_CONFIG.linkRoute.maxPoints`を通じてクライアントへ渡します。DB制約の8点はスキーマ7の固定契約です。

クライアントの`core/link-route-data.js`をリンクの正規化・保存変換・保存前検証で共用します。保存snapshotやビュー複製では点もコピーし、後続入力と参照を共有しません。保存データを維持したまま、描画時に`canvas/manual-link-route.js`で重複点・0長区間・同方向の共線点を整理します。厳密な座標一致を使い、折り返しと微小な折れは残します。

## モーダルの閉鎖とフォーカス

`core/modal-focus.js`の`registerModalOpen(id, overlay, preferredFocus, { onClose })`に、各画面の閉鎖処理を登録します。右上×と必要なキャンセルはその処理を呼び、背景クリックと`canvas/selection.js`のEscは`requestModalClose()`から同じ処理へ渡します。最前面だけを対象にし、非同期の閉鎖判定中は背景・Escによる確認の重複を抑止します。画面IDによる閉鎖関数の分岐と各画面の背景リスナーは持ちません。台帳の候補が開いている時は、Escで候補だけを閉じます。

閉鎖時の分類と条件は次のとおりです。

| 分類 | 対象 | 閉鎖条件 |
|---|---|---|
| 閲覧・選択・即時反映 | ダッシュボード、品質診断、Ping結果、管理接続・SSHヘルプ、経路ヘルプ、機器画像拡大、検索のビュー選択、台帳の配置先選択、印刷、表示設定 | ×・背景・Escで閉じる。即時反映した設定は戻さない |
| 未適用編集 | 台帳、個票、ビュー管理、配置管理、接続系統設定、機器・接続の一括編集、利用者管理・パスワード変更 | 台帳の行下書きは検証・確定し、invalidなら閉鎖抑止。個票・ビュー・配置は適用／編集継続／取り消し確認、系統・一括編集・利用者入力は破棄確認。利用者APIや一括適用中は閉鎖抑止 |
| 取込・破壊的操作の準備 | CSV取込、バックアップ復元、図面管理のファイル選択 | ファイル・検証結果などが残る時は破棄確認。検証・確定処理中は閉鎖抑止。最終取込・復元・差替え・削除の確認は別に維持 |
| 未確定変更の選択確認 | 適用／編集継続／取り消しの共通確認 | ×・背景・Escでは編集継続へ戻す。親の入力を破棄せず、確認overlayを除去する |

図面管理の登録・差替え・削除、調整モード、確定済みの位置・サイズ・不透明度・表示状態の扱いは変更しません。未配置機器はCanvasの配置補助パネルの「未配置」タブで扱います。使用しない旧モーダルのテンプレート・CSS・専用JavaScriptと選択状態は削除しました。

モーダルスタックは前面のz-indexと`aria-modal`、親の`inert`を同期し、Tab／Shift+Tabと外部へのフォーカス移動を最前面内へ制限します。表示中はCanvasを`inert`にして表示操作を隠し、最後の閉鎖で元のCanvas状態を復元します。閉鎖後は表示中・操作可能な起動元へフォーカスを戻し、隠れた親や別の前面モーダルの背後へ戻しません。×は`modal-close-btn`とneutral token、32px以上の操作領域、共通focus indicator、`aria-label="閉じる"`を使います。

## フッターの状態・表示操作

フッターは画面全幅に固定した高さ32pxのバーです。左に現在ビューの機器・リンク・選択件数と保存状態、中央に処理進捗・Ping結果・一時通知、右にCanvasの全体表示・縮小・倍率／標準表示復帰・拡大を置きます。右パネルの開閉・幅変更で操作位置が移動せず、図面・機器に重ならない配置とします。

`status_bar.php`が既存IDを維持して操作群を配置します。左の件数と保存グループは内容幅で隣接させ、保存バッジの固定幅と保存確認ボタンの空枠を設けません。確認ボタンは未確認時だけバッジ左隣に表示します。保存済みは控えめな文字表示、保存待ち・保存中は状態色の文字表示とし、失敗・競合は太字・背景・枠で区別します。別対象の保存中や保存結果が未確認の場合でも、残る競合を強調します。中央のPingサマリーと「結果を表示」は伸長しない一つのグループとし、サマリー直後にボタンを置きます。進捗と一時通知も中央に残し、長文は省略して全文をtitleへ保持します。右領域は180pxの固定幅です。中央の出現・消失では左の内容幅と右端位置を変えず、収まらない狭幅では左と中央だけを横スクロールさせ、1行の高さを維持します。ボタンは共通コンポーネントの24px版、フォーカスは共通の黄・黒を内側へ表示します。

`setBusy()`は中央の`busy-label`へ出力し、終了時に本文とtitleを消去します。処理中のPing結果・一時通知の非表示、Ping中の通知抑制、通常通知の3秒消去、直近Ping結果の保持と詳細モーダルを維持します。処理全体の失敗理由はPingサマリーとtitleにも含めます。保存状態判定・確認処理とズーム計算・Fit・標準表示復帰を共用します。ズームはCanvas初期化後に表示し、共通モーダルスタックに表示中のモーダルがある間だけ操作群を隠します。図面調整で管理画面を一時的に隠す場合、フォーカス復帰用の登録は維持したまま表示状態を再同期します。調整中は全体表示・ズームを利用でき、終了・取消・Esc・保存で管理画面が再表示された時は再び操作群を隠します。

## 通知の分類

`ui/toast.js`の`showStatusMessage(message, type = 'info')`は、追加操作が不要で画面変化だけでは分かりにくい結果をステータスバー中央へ表示します。`info`と`success`を受け付け、次の通知で置換し、3秒後に本文とtitleを消去します。長文は既存CSSで省略し、titleで全文を確認できます。読み上げはpoliteとし、同一文言の再通知では本文を書き換えません。

`showToast(message, type = 'warning')`は、操作不能・注意を`warning`、横断的な処理失敗を`error`として表示します。`success`と`info`は受け付けません。警告は5秒・polite、エラーは6秒・assertiveです。ステータスバーへ同じ文言をコピーせず、同一文言を別領域へ出し直す場合も元の表示を消します。位置は全幅でステータスバー直上の下部中央とし、狭幅では左右余白、折り返し、高さ制限と本文スクロールを使います。既存のz-indexを維持し、モーダル内で発生した処理失敗も前面へ表示します。

ビュー切替、モード開始・終了、機器配置、リンク作成、情報適用など、結果が画面上で明確な操作には通知を追加しません。フォーム固有の問題は`ui/field-errors.js`と項目近傍のエラー欄を優先します。複数行にまたがる台帳の入力検証など、エラーが分散する場合は短い警告を残します。操作方法はラベル、配置パレットの常設案内、ミニヘルプ、メインヘルプで説明します。

通常保存成功はステータスバー左側の保存状態を正とし、成功通知を出しません。保存失敗・競合・未確認では既存の状態と再試行・確認・再読込の導線を維持します。認証失効は永続バナーと保存ボタンの無効化で示し、401や失効後の保存操作で同じトーストを繰り返しません。バナーはfooter外の独立した要素とし、ステータスバー直上でビューポートへ固定します。footerのoverflowによるクリップと重なり順の制約を避け、モーダル表示中も再ログインリンクを前面へ表示します。

## Ping結果の表示

実行と最新監視状態の更新は`ui/toolbar.js`の`doPing()`と既存APIを維持します。`ping:updated`の開始イベントに対象ID・保存済みIP・開始日時を渡し、進捗イベントは経過時間だけを更新します。完了イベントは結果配列・完了日時・処理エラーを渡します。APIに途中の完了件数はありません。

`core/ping-result-data.js`が実行開始時の機器名・対象IPをコピーし、今回の対象IDだけを突合します。欠落結果は未確認、要求全体のエラーは全対象を理由付きの未確認として扱います。`modals/ping-results-modal.js`は直近1回をメモリに保持し、完了時はフッターの件数と再表示ボタンだけを更新します。新しい実行を開始すると前回の結果を置き換えます。モーダルの開閉・絞り込み・CSV出力で台帳の再描画や保存を行いません。

共通モーダルスタック・フォーカストラップ・Escを再利用し、結果一覧だけを内部スクロールさせます。失敗フィルターはfailureとtimeout、成功はsuccessで、skippedとunknownは「すべて」で表示します。台帳のNGとフッターの失敗件数はfailureとtimeoutの合計です。CSVは全件をBOM付きUTF-8・引用セル・CRLF区切りで出力し、数式文字列を先頭アポストロフィで保護します。履歴DB・永続ログ・バックアップ形式は変更しません。

表示は共通モーダルの外枠、台帳の`ledger-header`・`ledger-sheet-actions-bar`、共通の`modal-close-btn`、`base.css`の`table-dense`・`btn`、既存の状態色を再利用します。専用CSSはトークンによる余白、最大高さ、列幅、一覧内スクロール等の配置調整に限定します。集計は枠なし、機器名とIPは同じセルとし、理由は長さにかかわらずネイティブの`details`・`summary`で展開します。`summary`にはTab移動の対象となる`tabIndex`を明示し、共通フォーカストラップ内で操作できます。CSVは絞り込みと同じ操作欄へ配置し、下部の「閉じる」は設けません。


## キャンバス・コンテキストツールバー

`templates/components/canvas_context_toolbar.php`が共通外枠と機能別の`data-canvas-context`領域を持ち、`ui/canvas-context-toolbar.js`が一度に1つのcontextだけを表示します。通常時は非表示です。共通CSSは上部アプリバー直下の配置と機能に応じた狭幅時の配置を担当し、重なり順は`tokens.css`の`--z-canvas-context-toolbar`で管理します。図面調整・経路調整とも共通の背景・枠・影トークン、DADSボタンの`.btn`系とフォーカス表示を使い、従来の専用配色・丸いボタンのスタイルは持ちません。

図面調整は不透明度・位置/サイズのリセット・使い方・完了を表示し、狭幅では折り返します。管理モーダルは640pxを上限とし、サムネイルとファイル情報、表示切替、登録/差し替え/削除を扱います。調整開始で共通モーダル登録も解除し、完了後はCanvasへ戻ります。非表示設定は変えず、調整中だけ画像を表示します。全体表示は従来の`floor-plan:fit`を使い、Canvasのpan/zoomと図面設定は分離します。

機能は`showCanvasContextToolbar(id, onFinish)`で開始し、通常の終了処理で`hideCanvasContextToolbar(id)`を呼びます。context切替とESCでは、共通制御が前の表示を閉じてから`onFinish(reason)`を一度呼びます。終了理由は切替が`replace`、ESCが`escape`、明示的な終了が`finish`です。別contextの`hide`は現在の表示を閉じません。ESCの呼出しは既存のキーハンドラーに置き、前面モーダルの処理を優先します。

図面のモード・管理・不透明度は`modals/floor-plan-modal.js`、移動・四隅のリサイズとpointer/keyboard確定は`canvas/floor-plan-editor.js`が担当します。world座標で対角を固定し、縦横比とscale 0.05〜2を維持します。44pxのハンドルはCanvas倍率の逆変換で大きさを保ち、画面外の四隅もCanvas内から操作できます。Escは未確定gestureだけを取り消し、gestureがなければ調整を終了します。図面レイヤーは通常時に`aria-hidden="true"`、調整中に`false`とし、画像と四隅の操作名を支援技術へ公開します。

確定済み図面設定は`core/save-queue.js`のビュー別Mapへ投入し、従来の`save_resources`と専用`update_floor_plan_settings`を直列化します。通信中の後続操作は最後の確定snapshotへ統合し、応答で操作中の値を戻しません。通信断は共通の未確認状態と再確認へ接続します。図面設定APIの世代競合409は`details.conflicts`で対象ビューを示し、再読込まで送信を止めます。SQLiteの一時的なbusyは競合詳細のない409を返すため、通常の保存エラーとして値・調整モードを保持し、再試行できます。再確認では図面だけでなく送信時のビュー・配置・接続・メモも比較し、他画面の変更を最新世代で上書きしません。図面ファイル操作も同じ通信予約を使い、差し替えはDBの既存設定を保持します。エンドポイント・DBスキーマ・Canvasのズーム上限は変更しません。

共通contextは図面・接続経路・メモです。同じcontextの再表示は冪等とし、別contextへ切り替えるときは前の編集を終了します。外枠・説明文を含むクリック、pointerdown・pointermove、contextmenu、ホイールを遮断します。図面のpointerup/cancelはcapture対象、既存の経路・メモは各controllerの終了処理で扱います。

経路調整の右パネルは「経路調整」「自動経路」「？使い方」の3操作を等幅の3列に配置し、中央の「自動経路」の左右の間隔を均等にします。「自動経路」は現在のリンクがautoなら無効、調整開始後やmanualなら有効になり、確認後に手動経路を破棄して自動保存します。調整中は未確定previewを破棄して終了し、調整終了後のmanualにも同じ操作を使えます。権限・認証・Ping・図面調整・ビュー競合・選択の制限は開始操作と共通です。

フローティングはモード名と「折れを追加」「折れを削除」「完了」だけを表示し、区間未選択・方向・点数の状態表示と自動復帰ボタンは置きません。追加は青枠の副ボタン、削除は赤枠の副ボタン、完了は青の主ボタンを使います。ミニヘルプは右パネルの「？使い方」から開き、SSH接続のミニヘルプと同じ共通ダイアログ・`core/modal-focus.js`を使います。開く際は未確定のドラッグだけを破棄し、ヘルプ内のESCはヘルプだけを閉じます。閉じると起動元へフォーカスを戻し、経路と保存状態は変えません。

経路編集のpreviewはsession内だけに保持し、rendererが経路Mapへ適用してから既存の交差・hit・ラベル・選択描画を行います。透明な区間hitと中央のハンドルだけを重ね、交差表示の専用rendererは作りません。水平区間は上下、垂直区間は左右へ動かし、機器端点を固定します。`canvas/manual-link-route-edit.js`の折れ追加は隣接区間を伸縮させて2点の段差を作り、両側が機器端点ならU字にします。削除は近傍の2中間点を除き、必要なL字で前後をつなぎます。描画と編集で厳密な共線点整理を共用し、意図的な折り返しは自動削除しません。

開始時のauto→manual、pointerup、折れ追加・削除、自動配線復帰、矢印キー操作は確定済みリンクの経路フィールドだけを変更し、既存のview保存キューへ投入します。属性の未適用入力は混入させません。保存中の追加編集を許可し、ID再採番へ追従します。別pointerの終端は無視し、ESC・選択解除・ビュー切替では未確定previewだけを破棄します。外部からの経路・端点変更や409・権限失効では編集を終了し、古いpreviewの上書きを防ぎます。

## 配線経路と交差表示

`canvas/link-route-resolver.js`はauto/manualを解決し、同じ経路Mapをrendererと交差処理へ渡します。manualは保存中間点を優先し、端点は現在のplacementの中心から求めます。不正な手動データだけをautoへフォールバックし、保存値とdirty状態は変えません。配置がないリンクは従来どおり描画対象外です。

手動経路では、端点接続が斜めになる場合だけ先頭・末尾の折れ点を隣接区間の軸へ接続し直し、内側の点を保ちます。隣接区間が垂直なら境界点のy、水平ならxを機器中心へ合わせます。補助点の追加で上限を超えず、描画経路も最大8折れです。中間点0点は直線または横→縦のL字、1点はアンカーを通る端点側の補助区間で接続します。既に直交する接続は変更せず、機器の移動・寸法変更は保存経路の書換えなしで反映します。

autoの`canvas/link-router.js`は機器中心を端点として経路を一括計算します。500リンク以下では、他機器の内部通過、機器外の完全重複、24座標単位未満の近接平行区間、交差、経路長、折れ数、候補順の順で評価します。接続数に応じたoffset候補と機器内部で分岐する候補を使い、最大65候補に制限します。500リンクを超える場合は候補評価をせず、機器ごとの接続順で最大13レーンを循環割当します。高密度では重複や機器内部通過が残る場合があります。manualは両分岐で固定経路を優先し、通常評価ではID順で確定した手動区間を後続autoの評価対象へ登録します。セル番号が安全な整数範囲を超える有限座標は空間索引の広域項目として扱い、セル番号の加算が進まないループを避けます。

リンクID順と固定の候補順で同点を解決し、再描画順に依存しない経路を生成します。移動時は既存のフレーム単位更新で全経路を再計算します。先に決まった経路が後続経路の評価に影響するため、移動機器に接続するリンクだけの部分再計算は行いません。

`canvas/link-crossings.js`は元の経路を変えず、表示用SVG経路とラベル位置を計算します。空間インデックスで交差候補を絞り、低ID側を元の線で表示、高ID側の交差区間を経路距離のspanとして一度だけ検出します。表示用path生成だけを方式で切り替え、山形ブリッジは連続した二次ベジェ曲線、切れ目はSVGの移動コマンドによる非描画区間とします。ブリッジは水平では上、垂直では右へ膨らみ、逆向きでも山の側を維持します。共有区間の分岐・合流や端点接続は交差表現を付けず、近接交差は結合します。500リンクを超える場合の区間あたり候補8件・検索ノード32件・経路あたり交差候補64件の上限は両方式で共通です。ラベルは交差区間付近にある場合だけ近くの経路上へ移動し、文字幅を含む衝突回避は保証しません。

`canvas/renderer.js`はauto/manualとも元の完全経路をクリック判定に使い、切れ目部分や表示線の山の部分でもクリックできます。選択・hover中は共通の前景SVGで選択した方式の表示経路を縁取り付きで表示し、hover解除時に選択中の経路へ戻します。前景はポインター操作を受け取りません。ラベルは手動経路でも全長の中間位置を基準とします。自動計算結果・端点接続の再構成結果・交差表現はDBに保存しません。

`core/link-display-settings.js` は構成データから独立した表示設定を保持します。
「管理 > 表示設定」は管理者・閲覧者とも利用でき、交差の表現と接続関係の強調を即時反映します。
交差の表現は従来どおり `localStorage` の `netarium.linkCrossingStyle` に `bridge` または `gap` を保存し、初期値、不正値、読込・保存失敗時は `bridge` に戻して接続だけを再描画します。
強調は別キー `netarium.connectionHighlightEnabled` に `true` / `false` の文字列だけを保存し、初期値、不正値、読込・保存失敗時は OFF とします。
強調切替時はキャンバス全体を再描画し、両設定とも dirty・保存キュー・リビジョンへ接続せず、CSV・バックアップ・復元にも含めません。

強調対象は現在ビューの `selectedPlacementIds` が 1 件の配置を起点に、現在の配置・機器が存在する `getCurrentLinks()` の両端から無向の 1 ホップだけを求めます。
描画と選択変更のたびに再計算し、起点 ID や対象集合は保存しません。
未選択・複数選択、範囲選択中、接続作成中、メモ作成中、接続フォーカス中は通常表示に戻しますが、設定値は保持します。
機器情報パネルの編集状態には依存しません。
対象外の機器・接続は opacity だけで淡色化し、接続のヒット経路・hover 前景・系統色・Ping 状態は維持します。
印刷は独立した印刷モデルと描画を使い、この画面上の淡色化を反映しません。

## 接続系統とビュー内一覧

DBスキーマ9の`link_systems`は全ビュー共通の`id`・`name`・`color_key`・`resource_revision`を保持し、`links.system_id`はnullableな外部キーです。既存接続にはNULLを補完します。固定8色のcategorical paletteは`core/link-systems.js`と`css/components/link_systems.css`で管理し、UI状態色とは分離します。描画単位のMapで系統を解決し、auto/manualとbridge/gapで同じ色を使います。hoverは色を変えず強調し、選択はPrimary色の縁取りを追加します。印刷snapshotには系統色の固定HEXを投影し、後のマスタ編集から独立させます。

`LinkSystemService`と専用APIはマスタの世代で競合を検出し、管理者・CSRF・操作ロック・監査を適用します。使用件数は全ビューから集計し、使用中の削除を拒否します。マスタ変更はビュー世代を更新しませんが、復元等の全体操作を失効させるため`data_revision`を更新します。リンクへの割当はビュー集約保存に含め、既存の409処理へ入れます。

`create_link_system`の成功応答は、一覧・全体世代に加えて採番した`created_id`を返します。設定画面は登録直後の系統をこのIDで選択し、名称の一致や一覧位置では判定しません。同名の系統が存在しても、続く編集・削除は新しい系統のIDと世代を対象にします。

`ui/workspace-navigation.js`は現在ビューの機器／接続をタブで表示します。接続の検索はクライアントで行い、系統名と表示上の「未設定」も検索対象にします。系統専用の絞り込み状態は持ちません。行の単一選択とcheckboxの一括操作対象を分け、全選択は検索結果だけを対象にします。一括設定は系統・VLAN・ラベル・備考だけを対象とし、OFFは保持、ONの空値はクリアです。「変更内容を確認」で変更前後と空欄化を表示し、この段階ではデータを更新・保存しません。「戻る」は入力を保持して確認値を無効にします。最終適用時に対象・選択・権限・競合を再検証し、端点・ポート・経路を変えず、確認した変更をビュー保存キューへ1回投入します。viewerは一覧・検索・選択・系統閲覧のみ利用できます。

接続線の通常線幅は4、hover／selectedと前景の系統色部分は5です。選択の縁取り・hit経路・印刷専用線幅2.5は維持します。一覧行だけが`onLinkClick(link, { reveal: true })`を使い、接続情報への切替が成功した後に共有resolverのauto/manual経路を可視化します。`canvas/pan-zoom.js`は機器フォーカスと共用する左右パネルを除いた可視領域と、経路の各線分との交差を判定します。外接矩形だけでは、画面を迂回する手動経路を見えていると誤認するため使いません。一部でも見える場合はパンせず、全体が隠れている場合だけ経路の長さ中点を可視領域中央へ即時パンします。倍率・経路・保存状態は変更しません。checkbox・全選択・Canvas上の選択はこの可視化を呼ばず、未適用入力の切替を取り消した場合もパンしません。900px以下の行クリックでは既存の機器行と同様に一覧を閉じます。

一覧クリック側では全経路を追加計算しません。可視化対象のIDを`render()`から`renderLinks()`へ渡し、描画時に1回解決した経路Mapをpreview反映後に可視化にも使います。既存の経路キャッシュや無効化条件は追加せず、描画と可視化の経路を一致させます。

機器タブの台帳導線は`ledger:open-for-view`でクリック時の`viewId`を渡します。ダッシュボードと共用する`openLedgerWithFilters()`は、各項目の単一値と値配列を受け付け、未指定条件を初期化します。通常の`openLedger()`は表示ビューだけを解除し、他の条件を維持します。

台帳の表示ビュー、施設、フロア、状態、種別、IP登録、配置状態、保守期限は複数選択です。各`select[multiple]`の`option.selected`を選択状態の正本とし、空値の「すべて」optionは置きません。`getLedgerFilterValues()`は`viewIds`を数値配列、`facility`・`floor`・`status`・`type`・`ipPresence`・`placement`・`maintenanceExpiry`を文字列配列、`keyword`を文字列で返します。空配列はその項目で絞り込まないことを表します。項目内はOR、項目間と検索はANDで評価します。表示ビューは選択した`view_id`の配置から機器IDの和集合を求めます。ビュー名は候補・条件チップの表示にだけ使い、同名でもIDで区別します。

`ui/ledger-filter-picker.js`は元のselectを非表示にし、選択値を示すトリガーと`role="listbox"`・`aria-multiselectable="true"`の候補一覧を構築します。トリガーは0選択で「すべて」、1件でラベル、複数件で件数を表示します。矢印・Home・Endで移動し、Enter・Spaceで選択を切り替えて一覧を開いたままにします。Esc・Tab・フォーカス移動・外側クリックで閉じます。条件チップは各値の`{key, value, label}`から生成し、各「×」は該当値または検索だけを解除します。「条件を解除」は検索と全項目を解除し、機器チェックを外す「選択を解除」と区別します。

機器のチェック選択は、表示ビューの選択集合が変わった時だけ解除します。他条件・検索の変更では表示外のチェックも維持し、一括編集・Pingの対象に含めます。候補の再描画やビューID・機器IDの再採番では選択を追従させ、同じビュー集合ならチェックを解除しません。`fillLedgerSelect()`は候補更新後も選択値を保持し、施設・フロア・種別は候補から消えた選択値も条件として残します。ビューは消えたIDだけを解除し、残るビュー条件は維持してステータスバーへ通知します。機器の編集・権限・保存・CSVの処理は共用し、CSVは絞り込みやチェックに関係なく保存済みの全機器を出力します。URL・DB・API・バックアップに新しいフィルター仕様は追加しません。

ダッシュボードは「運用状況」（初期表示の7 KPI・監視・品質）と「資産・保守」（期限3区分のカード・既存の施設／フロア／種別内訳）に分けます。タブ切替は表示のみで、開く時と更新時に再集計します。`core/maintenance-expiry.js` の共通関数がローカル日付と暦年境界で5区分を判定し、年月のみは月末、うるう日の年加算は対象月末として扱います。不正値は除外し、元の値や既存品質診断は変更しません。台帳の期限条件が有効な場合は同じ月末補正で期限昇順に並べます。期限カードの `openDashboardLedger({ maintenanceExpiry })` だけが保守管理列を一時適用し、期限条件解除・閉鎖・別入口では保存済み列へ戻します。利用者による列の明示変更以外では localStorage を書き換えません。


## キャンバスメモ

DBスキーマ8の`canvas_notes`は`id`・`view_id`・`text`・`x`・`y`・`width`・`height`・`background_color`・`background_opacity`・`text_color`・`font_size`を保持します。本文は1000文字以内のプレーンテキスト、座標は非負の有限数、幅120〜2000・高さ60〜2000、背景透明度0.2〜1、文字サイズ12〜32、色は6桁HEXです。`Topology/CanvasNote.php`と`core/canvas-note-data.js`をAPI・バックアップ・クライアント保存でそれぞれ共用します。所属ビューの外部キーでcascadeし、変更・所属変更は対象ビューの世代へ反映します。

`canvas/canvas-notes.js`はfloor plan → links → notes → devicesの順のDOMレイヤーを描画し、本文に`textContent`と`textarea.value`を使います。背景はRGBAで描き、文字のopacityを変えません。メモは配線ルーターの障害物へ追加せず、Fitでは機器とメモの矩形を集計し、表示中のフロア図面があれば図面を優先します。

左のメモモードと選択メモは機器・配線・配置モード、図面調整・経路調整と排他にします。装飾・削除・完了は既存の共通コンテキストツールバーを利用します。背景・文字の色は各8色の四角を並べたプルダウンで選び、候補外の既存色も現在色の四角に表示して保持します。本文下書き・ドラッグ・数値装飾previewを確定モデルから分離し、本文確定、pointerup、色の選択、数値装飾change、削除で共通キューへ投入します。context終了では本文を確定し、未確定のドラッグと装飾previewを破棄して色一覧も閉じます。DOMをIDごとに再利用し、保存応答・採番でも入力欄を作り直しません。viewerは表示・テキスト選択のみで、APIでも管理者権限を要求します。

Webバックアップは`netarium-config`形式1／DBスキーマ11で、JSONの`manifest.json`と`data/netarium.json`だけを出力します。メモと接続系統・割当を含む構成10テーブル、`app_meta`4キー、画像参照メタデータを対象とし、画像実体・利用者・パスワード・認証状態を含めません。旧画像同梱形式2〜7は非対応で、スキーマ・アプリ版の完全一致を要求します。固定契約は[運用ガイド（復元）](operations.md#復元)を正本とします。

画像登録時は保存実体のSHA-256を記録し、旧行の空digestは初回出力時に保存名・サイズ・MIME・寸法が一致する実体だけをハッシュして補完します。復元ではこれらの属性とSHA-256が一致する既存実体だけを参照し、欠損・不一致の件数と機器ID／ビューIDをプレビューに示します。元メタデータはZIP内に残し、画像実体の作成・上書き・移動・削除・再変換と復元時の画像GCは行いません。復元前自動退避も構成情報ZIPです。利用者・パスワード・実行者を含む全セッションは変更しません。

Web ZIP単独では全損時の画像・利用者を復旧できません。画像実体・利用者を含む全損復旧には、サーバー管理者用の停止型完全バックアップCLI（`scripts/backup-full.ps1`／`scripts/restore-full.ps1`）を使用します。

## キャンバスの印刷

`canvas/print-model.js`は現在ビューのデータを印刷設定でfilterし、機器・配線・メモ・図面・タイトルの独立snapshotを作ります。機器は名称・種別・設定に応じたIPだけを投影し、認証情報・管理接続情報は含めません。非表示機器の端点を持つリンクを除外し、通常の全配置・リンクで解決した経路を保持したまま、印刷対象だけに現在のbridge/gapを適用します。全体boundsはONの要素から集計し、図面ONのfloorでは図面矩形を優先します。現在範囲はキャンバス寸法とpan/zoomを逆変換します。

`canvas/print-renderer.js`は通常canvasをcloneせず、独立SVGに配線・ラベルと、`foreignObject`内の機器カード・図面画像・メモを描画します。SVGアイコン・配線のラスター化処理は追加しません。IPを省略したノードは中心を維持して高さを詰め、メモの背景透明度を文字へ適用しません。SVGの`viewBox`と`preserveAspectRatio`で印刷範囲を収めます。

`modals/print-modal.js`と`templates/modals/print.php`は左パレットの独立アクション、左側の設定と右側の常時プレビュー、`window.print()`を提供します。設定変更で独立DOMを更新し、画面遷移や入力フォーカス移動は行いません。連続変更は生成世代で区別し、古い画像準備完了・失敗を現在の印刷可否へ反映しません。既存モーダルスタックでTab・Esc・起動元フォーカスを扱い、通常mode・selected・pan/zoom・dirty・保存キューへは代入しません。画像decodeとフォント準備を待ち、失敗時と閉鎖後の遅延完了では印刷を許可しません。設定は開くたびに初期化し、DB・backup・localStorageには保存しません。

`css/modals/print.css`は最大1280pxのモーダル内に360pxの設定欄と可変幅のプレビューを並べ、設定文字を13px・補助説明を12pxへ縮めます。850px以下では上下配置にします。印刷時は設定欄・モーダル見出し・操作ボタン・通常ツールバー・パネル・ステータスバーを除外し、独立した印刷専用DOMだけを出力します。用紙寸法を固定せず、`@page`で向きのみを指定し、ページ高へ1ページ分を収めます。紙・PDFの描画、文字の可読性、ブラウザー別の向きと改ページは人による受入確認の対象です。

## 保存と競合制御

フロントエンドは確定済みのビュー、機器、配置、リンク、メモと、機器編集の下書きをブラウザメモリ上に分けて保持します。`device-drafts.js`は台帳・個票・右プロパティパネルごとに下書きを保持し、検証後に変更項目だけを現在の機器へ確定します。未適用入力は配置や別機器の保存へ混入させません。通常保存は`save_resources`へ変更対象だけを送り、機器属性は機器単位、配置・配線・メモ・ビュー設定はビュー単位の`resource_revision`で競合を判定します。別機器・別ビューの変更は独立して保存でき、同一機器の別フィールドや同一ビュー内の別配置・メモは自動マージしません。

`save_resources`は機器・ビューの`create` / `update` / `delete`を配列で受け取り、更新・削除では`expected_revision`を要求します。ビュー更新ではそのビューの配置・リンク・メモをまとめて送信します。新規IDはサーバーで採番し、応答の`id_maps`（メモは`canvas_notes`）でブラウザの仮IDを置き換えます。応答は変更機器、変更・削除影響ビューとその構成、削除IDを返し、未変更リソースを上書きしません。要求内の変更は一つのトランザクションで確定し、一件でも競合した場合は全件をロールバックします。

`data_revision`（API応答の`revision`）は全体の変更世代です。通常保存の競合判定には使わず、CSV取込、復元、明示的な全体スナップショットAPI`save`の整合確認に使用します。`save`は通常画面の保存経路ではなく、全体操作と合成データ投入用に残します。Ping結果は`monitor_revision`として別管理します。

全体保存`save`でも`canvas_notes`は必須の配列です。省略・null・不正型は400で拒否し、既存メモとビュー世代を変更しません。明示した空配列だけがメモ全件削除を表します。本文入力にはUTF-16単位の`textarea.maxLength`を使用せず、共通保存検証とAPIでUnicodeコードポイント1000文字の上限を適用します。上限超過時は送信せず入力を保持し、本文を修正して再保存できます。

機器削除は関連配置・リンク・画像・監視状態を同時に削除し、影響するビューの世代も更新します。図面の登録・削除・表示設定はビュー世代を検査します。機器画像の専用操作は従来の全体世代検査を維持します。スキーマ6で導入したトリガーはスキーマ7の経路変更、スキーマ8のメモ変更、スキーマ9の系統割当にも適用し、全体保存・CSV・復元を含む各保存経路のリソース世代を更新します。ID・世代のカウンターは復元で巻き戻しません。

機器削除の応答では、削除に伴う配置・リンクの除去だけを未送信のビュー編集と判定しません。保存中に同じビューへ追加入力があり、応答にも他利用者による別の変更が含まれる場合は、追加入力を保持してそのビューを競合として保留します。更新された世代番号で他利用者の変更を上書きしません。

機器画像のコミット後整理に失敗した場合は、保存成功と`post_processing_required`を返し、監査にも後処理要対応として記録します。機器削除を再送せず、残ったGCを管理者が確認します。503を含む5xx応答や不正な応答だけではコミット成否を断定できないため、画面は保留保存を維持し、保存状態の確認を要求します。

HTTP 409では構造化された競合対象を保留し、その対象に依存しない変更は共通保存キューで保存を継続します。競合対象の再読込は取得データ全体でローカルstateを置き換えず、対象と必要な参照関係だけを更新します。自動マージ・自動上書きは行いません。通信不明時は送信時のスナップショットと対象の世代・内容で確定状況を確認し、確認中の追加変更は残します。新規作成の応答を失った場合はIDを推測して再送せず、最新データを再読み込みします。SQLiteの`busy_timeout = 5000`を維持し、書込み待ち超過はHTTP 503で変更を確定せず返します。WALや常時接続、リアルタイム共同編集は導入しません。

保存キューへ投入する境界は、台帳では機器行を離れる時、個票・機器詳細・接続情報・ビュー設定では「適用」、配置移動では`pointerup`です。同じ行内のセル移動、詳細入力の項目移動や入力停止では保存しません。台帳・個票のボタンは下書きがある時は「適用」、ない時は確定済み変更の送信・再試行を行う「保存」と表示します。台帳の「適用」は保持中の行下書きをまとめて検証・確定します。上部「保存」は確定済み変更の即時送信・再試行だけを行います。詳細画面を閉じる・対象を変える時は「適用」「変更を取り消す」「編集を続ける」を選び、すでに確定・送信した操作を取り消しで巻き戻しません。保存通信中も次の下書きを編集でき、古い保存応答やID再採番で入力を失わないよう保持します。

接続情報はラベル・系統・VLAN・接続元・入れ替え・接続先・経路・備考の順で構成し、機器名・IPアドレスとポートを同じ端点枠にまとめます。`property-panel.js`の入れ替え操作は、反転状態と入力中のポートを未適用の下書きとして保持し、モデルや保存キューを変更しません。ポート名が左右で同じ場合も方向の変更を未適用として検出します。適用時は全入力を検証してから機器IDとポートを一括反映し、manual経路の中間点順を反転します。「変更を取り消す」や閉鎖時の取り消しは未適用の反転だけを捨て、適用済みの向きを巻き戻しません。

経路調整は接続属性の「適用」と別の確定境界を持ちます。auto→manualの開始時、ドラッグの`pointerup`、矢印キー、折れ追加・削除、自動経路への復帰でビューの変更を共通保存キューへ投入します。`pointermove`ではpreviewだけを更新し、モデルや保存snapshotを変更しません。応答待ちの操作は並列送信せず、旧応答から受け取ったビュー世代で最新の確定状態だけを次に保存します。

経路保存の409では編集中のpreviewを破棄して調整を終了し、最新の確定済み未保存経路と未適用属性を保持します。競合ビューは自動再送せず、独立した変更の保存は続けます。接続情報の既存の「競合したビューを再読込」で破棄を確認してから対象ビューを復元し、再読込後に調整を再開できます。viewerは保存済みのmanual経路を読み取れますが、編集操作と`save_resources`は許可しません。

機器属性の検証は`core/device-validation.js`の`validateDeviceValues`で正規化済み値とフィールド別エラーを返します。`core/device-drafts.js`の確定経路と個票・右パネルが利用し、一括編集でも同じ制約を利用できます。`ui/field-errors.js`は支援説明の`aria-describedby`を保持してエラーを関連付けます。設置場所候補は`ui/location-suggestions.js`でビュー・機器の既存値をtrimし、完全一致の重複を除いて生成します。ネイティブdatalistへ関連付けるだけで候補選択を強制せず、施設・フロアの変更で配置を移動しません。

下書きを一括確定する際は、各候補の形式・長さ等を検証してから全候補を組み立て、確定後の機器集合でIP重複を検証します。確定前の集合とは比較しないため、IPの交換や他行でIPを空欄にする付け替えを拒否しません。重複等の検証エラーがあれば、stateと全下書きを保持します。

台帳の属性一括編集は`core/device-bulk-edit.js`で接続方式・ポートを含む11項目を定義し、開始時の選択IDと保存対象属性のスナップショットを保持します。変更する項目だけを正規化し、全対象を個別編集と同じ制約で検証してから一括反映します。対象の未適用下書き、属性変更、削除、既知の競合があれば全件を拒否します。確認後の適用時にも再検証し、配置・ビュー・監視状態は変更しません。台帳再描画・選択解除後に既存のDirty化と保存キューへ接続し、DB・CSV・バックアップ形式を変更しません。

機器画像アップロードは`core/device-image-api.js`から共通`apiFetch`を使い、multipart要求にもCSRFヘッダーと同一オリジンのcookieを付与します。対象の`resource_revision`が未確定の新規機器は待機理由を表示します。画像応答は画像一覧と全体世代だけを更新し、機器属性の保存世代や下書きを更新しません。

画像登録は`save-queue.js`の`waitForActiveResourceSave`で進行中のリソース保存・保存状態確認を待ち、その応答を反映した全体世代を要求へ設定します。この待機だけでdebounce待機中の変更を送信したり、未適用下書きを確定したりはしません。

新規スタンプ配置と既存機器のキュー配置は、その場で確定済みstateへ反映し、最後の配置から800ミリ秒待って連続操作をまとめて保存します。配置モード終了・ビュー切替・上部「保存」では待機中の変更を即時送信します。競合対象の再読込で保存可能になった依存変更も、追加の保存操作を求めず保存キューへ戻します。

バックアップ復元は`data/temp/operation.lock`のプロセス間ロックで制御します。保存、CSV、図面、図面画像配信、Ping、バックアップ出力・プレビューは共有ロック、復元確定は排他ロックを取得し、復元中または競合中はHTTP 409で拒否します。復元プレビューには、その時点の現行`data_revision`と`monitor_revision`を記録し、確定時に一致しなければ再プレビューを要求します。復元後はバックアップ内の世代をそのまま戻さず、復元直前の現行世代から新しい`data_revision`と`monitor_revision`を発行するため、古い画面からの更新を拒否できます。

## 監査ログと記録境界

管理操作（認証成否、利用者変更、構成保存と機器完全削除、CSV入出力、バックアップ出力、復元）の監査ログは、復元対象のSQLite DBではなく、ファイルシステム上の`<storage_dir>/logs/audit`へJSON Lines形式で記録します。DB復元によるデータ置換が発生しても、過去の監査履歴が上書き・消去されない記録境界を形成しています。

各操作は処理の開始境界で32桁16進数の調査用ID（`request_id`）を生成し、`outcome="started"`を同期追記します。監査ログの書き込み失敗や容量上限（256MiB）超過時は、HTTP 503やCLI非ゼロ終了で停止し、状態変更を開始しません。

操作完了後は同一の`request_id`で`success`、`failure`、または`post_processing_required`を記録します。APIの正常・異常レスポンスにも`request_id`を含めることで、クライアント側の事象とサーバー側の監査履歴を紐付けて調査できます。また、バックアップ復元では`data/logs/restore.log`にも同一の`request_id`が記録され、復元履歴と監査ログを相互に照合できます。


## 認証と権限

- `admin`: 機器、ビュー、リンク、図面、CSV、品質診断、バックアップの管理とPing実行
- `viewer`: 保存済み情報とPing結果の閲覧（Ping実行は不可）
- 利用者の`role`、`is_active`、パスワード変更はDBで管理し、保護対象のページ、API、図面配信で毎回状態を再確認します。role変更は次回要求で反映し、停止またはパスワード変更は既存セッションを失効させます。
- 認証確認中のSQLite busy／lockedはセッションを破棄せず、要求を503で拒否します。APIは既存の例外応答、通常ページ・ログイン入口は公開用の平文エラーを返し、DBの詳細やログインへのリダイレクトを返しません。ロック解除後も利用者状態を再照会するため、停止・パスワード世代変更・旧bcrypt禁止による失効を迂回しません。初期登録完了マーカーは既存値がある場合と利用者0件の場合に読取りだけで戻り、未補完の既存DBだけへ競合安全な補完INSERTを行います。
- ログイン試行制限はセッションへ保存せず、`login_rate_limits`へユーザー名単位で保存します。CSRFとユーザー名の検査後、短い`BEGIN IMMEDIATE`内で制限確認と照合枠の消費を確定します。`failure_count`は失敗と照合中の予約を含み、5枠で300秒間ロックします。利用者SELECTのカーソルを閉じてからトランザクション外で照合するため、Argon2idの処理中に全DBのwriter lockを保持しません。成功時は予約を含めて制限を解除し、`last_login_at`更新と同じ短いトランザクションで確定してからセッションを作成します。中断・照合後の保存障害でも予約は消費済みとして残り、期限または既存の解除操作で回復します。POST中のSQLite busy／lockedは秘密やDB詳細を出さず503とし、その他の内部障害は500を維持します。
- ログインのユーザー名はtrim後に共通の`validateUsername()`で3〜50文字の半角英数字・`_`・`-`・`.`を検査します。不適合な値は通常と同じ認証失敗とし、利用者照会・試行制限保存・横断失敗集計を行いません。フォームへの再出力と監査の`subject_username`記録も行いません。保存関数も同じ条件で不適合キーを拒否します。適合するキーのtrim・ASCII小文字化、5回／300秒ロック、成功時解除は維持します。既存行の一括削除・DB縮小・スキーマ変更は行いません。
- 新規設定は12～128 Unicodeコードポイント、UTF-8最大512バイト。NUL・不正Unicodeを拒否し、trim・正規化・切り捨てなし。PHP／JSの順序は不正Unicode→512バイト超→128コードポイント超→12未満→確認不一致です。setup・利用者作成・本人変更・管理者再設定・復旧CLIで共通検証とArgon2id生成を使います。初期costは`memory_cost=19456` KiB、`time_cost=2`、`threads=1`で、非対応時のbcrypt fallbackはありません。ログイン／現在値に新規設定条件を再適用せず、旧bcrypt成功ログインでrehashしません。全bcryptを明示変更・再設定・CLIで移行し、移行期間終了時は`config/app.php`のbool `allow_legacy_bcrypt=false`でログイン・現在値とも旧照合を拒否します。明示移行と HTTP worker への設定反映は[運用ガイド](operations.md#パスワードの明示移行169)に従い、実 FastCGI の生成・照合と単発／同時負荷を配備先で確認します。
- `allow_legacy_bcrypt=false`は旧bcrypt利用者の既存セッションも次の保護要求で拒否します。`check-install.php`は`password_algorithm`、`password_options`、`allow_legacy_bcrypt`、停止済みを含む全bcrypt件数`legacy_bcrypt_users`を報告します。原則v1.0.0前は残存件数0かつ旧照合禁止で判定します。
- 標準 PWDB 3,000 件を非公開 `resources/password-blocklist` から固定 SHA-256 検証して全体照合します。管理者の任意追加辞書は `<StorageDir>/password-blocklist` の別 manifest で整合性を検証し、未設定時は標準だけで動作します。有効登録後のデータ異常は新規設定を拒否します。全体反復・ユーザー名／製品名由来も拒否し、原入力は不変、既存認証に遡及せず、ブラウザへ一覧を配布しません。
- 本人変更はDB上の利用者単位5回／300秒制限で、照合と世代更新を`BEGIN IMMEDIATE`内に直列化します。ログイン／再認証の300秒内5対象失敗は監査警告のみで、接続元によるロックを追加しません。集計保持1時間、失敗10,000・警告2,000行。`REMOTE_ADDR`以外の転送情報は信頼しません。
- 管理者登録・再設定・復旧CLIは`must_change_password=1`を保存し、本人変更まで通常ページ／業務・管理・画像APIを拒否します。初回画面と本人変更・CSRF付きログアウトだけを許可します。既存利用者と初期setupは0。新旧同一秘密の解除を拒否し、完了時に0・世代増加・再ログインを要求します。
- 初期setupは配備時に生成した一回限りのbootstrap秘密を要求します。平文は管理者専用の非公開ファイル、SHA-256と完了状態は既存`app_meta`へ保存します。`BEGIN IMMEDIATE`取得後の閉鎖再確認、秘密照合、admin作成、digest消去と完了記録を一体で確定し、監査開始・終端失敗はrollbackします。秘密管理・監査とCOMMITの境界・復旧は[アーキテクチャ](architecture.md#認証と権限)を参照してください。

更新系POST APIはCSRFトークンを要求します。セッションCookieはHttpOnly、SameSite Strictで、HTTPS時にはSecure属性を付けます。

## 配備・更新の境界

`scripts/setup-iis.ps1`は、公開領域を`<InstallRoot>\public`、実行時データを`<InstallRoot>\data`へ分け、IIS FastCGI、ハンドラー、要求サイズ、ACL、初期DBを一度に構成します。既存の別配置からの移行は提供せず、同じ公開領域を使う再実行だけを許可します。

`scripts/update.ps1`は、保守ページとIISの要求拒否で入口を閉じ、排他ロックを取得してからプログラムマニフェストだけを差し替えます。`data/`と`config/app.php`は更新対象外です。DB移行はリリースを起動したときの既存マイグレーションだけを使用し、失敗時はプログラム、実行時データ、設定、IIS状態を同一スナップショットから復元します。

新配布物のルートファイルは`bootstrap.php`・`version.php`・`config/app.example.php`です。旧ルートの`auth.php`・`database.php`は新リリースに含めません。ただし配備スクリプトの`RetiredFiles`は旧版更新・撤去の管理メタデータとしてこの2ファイルを追跡します。更新前snapshotに元の存在と内容を保存し、snapshot取得後に撤去、rollbackでは旧版の状態を復元します。これはアプリケーションの互換shimではありません。手順は[更新ガイド](update.md)を参照してください。

`scripts/check-install.php`はCLIからDBスキーマ、外部キー、実行時ディレクトリ、図面メタデータと画像ファイルの整合性を確認します。`scripts/verify-security.ps1`はログイン、API認証、初期設定ページ、非公開パスをHTTPで確認します。

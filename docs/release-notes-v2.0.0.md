# Netarium v2.0.0 リリースノート

Netarium v2.0.0 は、建物・フロア階層の導入、2.5D の**建物ビュー**と 2 棟比較、ビュー非依存の**共通接続**とポート単位の VLAN 管理、配置移動の取り消し・やり直し、**データ品質診断**の「設定不要」、および 4 タブ構成のダッシュボードを追加するメジャーリリースです。
データベーススキーマを 23（v1.5.2）から 29 へ更新し、Web 構成情報 ZIP（`netarium-config` 形式 1）および停止型完全バックアップ ZIP（`netarium-full` 形式 1）は形式バージョン 1 を維持します。

## 主な変更

### 建物・フロア階層とビュー管理の統合

- **「建物・フロア・ビュー管理」への統合**：管理者は建物→フロア→ビューの折りたたみツリーと右側の編集画面で、建物とフロアの作成・編集・削除、ビューの新規作成・移動（「既存ビューを追加・移動」）、代表物理配置ビューの指定を一画面で操作できます。建物やフロアを削除すると、所属を失うビューと機器は未分類になり、接続は削除されません。
- **ビュー検索と設置フロアの刷新**：ビュー検索では現在のビューへの経路だけを初期表示で展開し、ビューが 1 件だけのフロアは候補から直接開けます。機器には任意の「設置フロア」を追加しました。物理配置図の未配置機器は既定で同じフロアと設置フロア未設定に絞り、必要に応じて別フロアの機器も表示できます。別フロアのビューへ配置しても、台帳の設置フロアは変わりません。
- **旧施設・旧フロア文字列の扱い**：通常画面での旧文字列の編集、検索、推薦を終了しました。設置フロアが未分類で旧情報がある機器に限り、個票に「現在の所属ではありません」と明記して読み取り専用で表示します。

### 建物ビュー（2.5D 表示・フロア間接続・2 棟比較）

- **2.5D 積層表示と位置合わせ**：「建物・フロア・ビュー管理」で「建物ビューを使用する」をオンにした建物は、ビュー検索の「建物全体」から各階の代表物理配置ビューを 2.5D で表示できます。閲覧者も利用できます。管理者は「位置合わせモード」で、元の図面設定と機器配置座標を変えずに各階の拡大率、XY 移動、回転を調整できます。
- **フロア間接続の模式表示**：代表物理配置ビュー上の直接配置または配置済みラック内の搭載機器（棚板を含む）で位置が一意に決まる機器を対象に、異なる階を結ぶ共通接続を機器ペア単位で集約して模式線で表示します。接続明細から機器個票の「接続・ポート」を開けます。閉じると元の建物ビューと視点に戻ります。
- **2 棟比較と建物間接続**：左パネルの「建物を追加」から建物ビューが有効な別棟を 1 棟追加し、「基準フロア」で高さを揃えて並べて確認できます。「フロア間接続を表示」と「建物間接続を表示」を切り替えて確認でき、比較中は位置合わせの編集を無効化します。

### 共通接続、ラック端点、ポート単位の VLAN 管理

- **ビュー非依存の共通接続と集約表示**：接続をビューから独立して保存するよう変更し、論理構成図とフロア物理配置図では両端の位置が決まる共通接続を表示します。ビューの削除や機器の配置解除では接続を削除せず、手動経路はビューと機器ペアごとに保持します。同じ表示アイコンの組（機器ペア、物理配置図では機器またはラックアイコンの組）の接続は 1 本に集約して「×N」で本数を示し、明細から個別に編集・削除できます。
- **物理配置図と印刷のラック端点表示**：物理配置図に配置したラックアイコンから、搭載機器・棚板機器と他機器または別ラックを結ぶ共通接続を自動経路で表示します（同一ラック内で完結する接続は描画しません）。画面と印刷の両方で破線枠のラックカードに揃え、印刷設定の「印刷する機器」でラックの有無を切り替えられます。
- **機器個票「接続・ポート」とポート単位の VLAN 設定**：機器個票に「接続・ポート」タブを追加し、登録済みポート、「ポート未指定の接続」、「未接続」（Netarium 上で接続未登録の状態）を分けて管理できます。VLAN 設定の保存先を共通接続から各ポート（1 行・200 文字以内）へ移し、両端ポートが保存済みの接続では相手の VLAN 設定を確認して双方向に上書き確認付きでコピーできます。接続を解除してもポートとポート VLAN は台帳に残ります。
- **右パネルの整理と旧記録の解消**：右側の「接続情報」は両端を機器 ID 昇順に表示し、ポート名と VLAN 設定の編集、入れ替え操作の廃止、経路操作の配置変更を実施しました。右側の機器情報パネルからは「このビューから外す」ボタンを廃止し、ビューからの配置解除を「表示するビューを選択」と Delete キーに集約しています。移行時に一意に統合できなかった旧接続は左パレット「一覧」の「要確認」から「新規接続する」または「旧記録を削除する」で解消でき、旧接続から退避した「未移行VLAN」（ポートへ自動転記しません）は再設定または確認付きの「未移行設定削除」で整理できます。

### 機器個票 4 タブ化、配置移動の履歴、品質診断、ダッシュボード 4 タブ化

- **機器個票「Config管理」タブの統合**：機器個票を「機器・設置・資産」「管理・保守・状態」「接続・ポート」「Config管理」の 4 タブに再編し、Config の閲覧、登録、行単位差分比較、選択削除を個票内へ統合しました。
- **配置移動の取り消し・やり直し**：管理者は論理構成図・フロア物理配置図の機器と、フロア物理配置図のラックアイコンのドラッグ移動を、ビューごとに最大 20 件まで「元に戻す」「やり直す」で操作できます。狭幅画面では「操作履歴」メニューから操作でき、キーボードショートカットにも対応します。
- **データ品質診断と「設定不要」**：共通接続のポート未指定と機器の保守期限未登録を情報として追加し、設置フロアが一致しない配置済みラックも警告します。管理者は、入力しない IP アドレス、推奨項目、端点ポート、保守期限を項目または端点単位で「設定不要」にできます。通常件数から除外し、「設定不要も表示」から確認・解除できます。
- **ダッシュボードの 4 タブ化**：ダッシュボードを「運用状況」「資産・保守」「ネットワーク」「データ品質」の 4 タブに拡張しました。「資産・保守」で「年度別」と「残存期間別」の保守期限見通しと機器内訳・ラック一覧を確認でき、「ネットワーク」でポート・共通接続・IP 管理集計、「データ品質」で保存済み DB 基準の診断サマリーと項目別登録率（「設定不要」の機器を分母から除外）を確認できます。

### 利用ガイド刷新、CSV、安定性・セキュリティの改善

- **利用ガイドと台帳 CSV**：ブラウザ内利用ガイドをトップ＋機能別 5 ページの全 6 ページへ再構成し、スクリーンショットを更新しました。台帳 CSV（固定 20 列を維持）は現在の建物名・フロア名を `facility`・`floor` に出力し、取込では既存階層名に一意一致した場合だけ設置フロアを更新します（CSV からの階層作成・所属解除は行いません）。「CSV取込仕様」の自動折りたたみ、取込後の検索・絞り込み維持、51〜100 文字の既存フロア名一致登録にも対応しました。
- **描画最適化と不具合・セキュリティ修正**：機器選択変更時の接続線再描画の省略、棚板・台帳一括操作・メモ下書き・機器画像更新の保存整合保護、一時的 409（`operation_busy`）と版競合・復元プレビュー失効の区別、Ping の `TTL expired in transit` 判定と到達性変化時の状態整合、画像配信時のセッションロック早期解放、セッション有効期限と Docker の `session.upload_progress.enabled = 0` 設定、未知・無効ユーザーログイン時の Argon2id ダミー照合、静的 HTML への CSP 適用と監査ログ共有状態のアトミック更新を実施しました。

## アップデート手順（v1.5.2 からの更新）

Netarium v1.5.2（DB スキーマ 23）を含む既存の対応バージョン（DB スキーマ 11〜28）から v2.0.0 への更新では、中間バージョンのプログラムを順次適用する必要はありません。
更新後の起動時および `scripts/check-install.php` により、データベーススキーマが自動的に 29 へ順次移行されます。

### 1. 更新前の完全バックアップ取得

作業前に、停止型完全バックアップを取得してサーバー外へ保管してください。

- **Windows / IIS 環境**：管理者 PowerShell で `scripts/backup-full.ps1` を実行します。
- **Docker 環境**：`bash scripts/docker-backup.sh` を実行します。

### 2. プログラムの更新

環境に応じた手順で更新を実施します。

- **Windows / IIS 環境**：
  新バージョンの配布資材を展開し、管理者 PowerShell で `scripts/update.ps1` を実行します。手順と前提条件は [更新・ロールバックガイド](update.md) を参照してください。
- **Docker 環境**：
  ソースビルド構成（`compose.yaml`）では最新資材を取得して `bash scripts/docker-update.sh` を実行します。事前ビルド済みイメージ構成（`compose.image.yaml`）には固定タグ `ghcr.io/lgug-jp/netarium:2.0.0` を設定しているため、利用前に GitHub Releases および GitHub Packages で公開状況を確認した上で `bash scripts/docker-update.sh -f compose.image.yaml` を実行してください。手順は [Docker 配備・運用ガイド](deployment-docker.md#7-更新ロールバック手順) を参照してください。

### 3. 更新後の確認と新版バックアップ取得

更新完了後、管理者は再ログインして構成図、台帳、接続・ポート、更新対象データの表示を確認してください。
正常稼働を確認した後に、速やかに v2.0.0 環境の停止型完全バックアップを新規取得して外部へ保管してください。

## 互換性と運用の注意点

- **DB スキーマとバックアップ形式**：DB スキーマは `29` です。Web 構成情報 ZIP（`netarium-config` 形式 1）および停止型完全バックアップ ZIP（`netarium-full` 形式 1）は形式番号 `1` を維持します。
- **直接 DB 更新と ZIP 復元の違い**：
  - **直接 DB 更新**：既存の SQLite DB（スキーマ 11〜28）をそのまま新版へ引き継ぎ、利用者、認証状態、全世代 Config、画像実体を保持したままスキーマ 29 へ移行します。
  - **Web 構成情報 ZIP 復元**：構成 29 テーブルとディスク上の実体と一致する画像参照だけを置換します（Config は各機器の直近 1 世代を保持）。利用者、パスワード、認証状態、既存セッション、画像実体は変更しません。
  - **停止型完全バックアップ ZIP 復元**：SQLite DB 全体（利用者、論理削除状態、採番状態、全世代 Config を含む）と画像実体をバックアップ時点へ戻し、既存セッションを失効させます。
- **バックアップ復元互換性（`BackupCompatibilityPolicy`）**：
  - **順方向復元**：同一 MAJOR 内の順方向／同一版（`source <= target`、正規安定版 SemVer かつ厳密整数スキーマ `11`〜`29`）に加え、既存データ保持のため、元アプリ版が正規の安定版 SemVer `1.0.0`〜`1.5.2` かつ元スキーマが厳密整数 `11`〜`23` のバックアップに限り `2.x` への順方向復元を受け付けます。
  - **逆方向および範囲外の拒否**：新版から旧版への逆方向復元（同一スキーマを含む）、`2.x → 1.x`、`1.5.2` を超える `1.x → 2.x`、非正規の版表記（先頭ゼロやプレリリース表記など）、未知形式、未対応スキーマは前段検査で拒否します。
- **移行時のデータ保持と確認事項**：
  - ビューの旧施設・フロア情報から建物・フロアを作成し、機器は既存・生成済み階層に一意に照合できる場合だけ紐付けます。建物ビューは、新規建物ではオフ、スキーマ 25 以下から引き継いだ建物ではオンになります。
  - 一意に変換できない旧接続は保留します。共通接続に引き継いだ非空 VLAN は未移行 VLAN へ退避し、ポートには自動転記しません。移行後は左パレット「一覧」の「要確認」や「データ品質診断」で確認してください。
- **台帳 CSV の互換性**：20 列形式を維持し、`facility`・`floor` 列に現在の設置建物名・フロア名を出力します。旧 19 列形式や列順の異なる CSV は取り込めません。
- **旧バージョンへの切り戻し（ロールバック）制約**：スキーマ 29 へ移行した DB に対してプログラムコードだけを切り戻すと起動拒否や不整合が発生するため、コード単体の切戻しは行わないでください。旧版へ戻す場合は、更新前スナップショットから同時点のプログラム・DB・画像・設定を一括復元してください。
- **完全バックアップ ZIP の対象外データ**：環境設定ファイル（`config/app.php`、`.env` など）、Web サーバーログ、監査ログ、セッションファイル、SSL/TLS 証明書等は停止型完全バックアップ ZIP に含まれません。サーバー管理者側で別途保全してください。

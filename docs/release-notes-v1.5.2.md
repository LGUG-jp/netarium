# Netarium v1.5.2 リリースノート

Netarium v1.5.2 は、ラックビューおよび棚板管理の操作性向上、ラック印刷の名称表示改善、機器詳細パネルからの個票表示導線の追加、および構成図上の機器名視認性の改善を行うリリースです。
データベーススキーマ（23）およびバックアップ形式（形式 1）に変更はありません。

## 主な変更

### ラック・棚板の操作性と視認性の改善

- **空き U 範囲選択のマウス解放時自動確定**：ラックへの機器搭載および棚板追加において、マウスで空きスロットの範囲を選択してボタンを離した時点で設定画面が 1 回開くようになりました（1 U クリック・複数 U・左右全幅・ハーフ幅に対応）。タッチ・ペン・キーボードによる段階的な範囲選択と、ツールバーからの手動確定・キャンセル操作も維持しています。
- **ラック搭載モーダルの 2 ペイン化と機器選択・登録の刷新**：左ペインに機器の選択・新規登録および現在の搭載位置、右ペインに搭載先の設定を配置しました（狭幅画面では 1 列表示）。未入力状態からの候補表示、アイコン付き種別フィルタと名称・IP の AND 検索、検索欄直下への候補重ね表示と独立スクロール、新規登録時の種別別初期名追従および任意 IP 入力に対応しています。
- **棚板設定の 2 ペイン化・連続機器追加と種別アイコン表示**：棚板設定画面をラック搭載と共通の 2 ペイン構成に統一しました。新規棚板をサーバーへ保存・確定した後は、モーダルを閉じずにそのまま左ペインから複数台の機器を連続追加でき、搭載済み機器一覧の右端にある `×` ボタンから個別に取り外せます。また、機器の追加・取り外し後も同じ画面のまま棚板名や設置位置を保存できます。ラック図上の棚板ブロックには、搭載機器の種別アイコン（最大 8 台＋残数 `+N`）と総台数を表示します。
- **ラック搭載図の印刷における名称表示の調整**：搭載ブロックの幅・高さと実測文字幅に応じて、機器名の文字サイズ（12／11／10px）と折り返し・末尾省略を調整します。名称表示を優先し、IP アドレス・機器種別は残り領域へ配置します。長い棚板名でもラック内の台数表示を維持し、右側の所属機器明細を全文折り返して出力します。

### 機器詳細パネルと構成図表示の改善

- **機器詳細パネルに「個票を開く」を追加**：全ビュー（論理構成図・フロア配置図・ラック搭載図）共通の右機器詳細パネル上部に「個票を開く」ボタンを追加し、「リンクをコピー」と横並びに配置しました（狭幅画面では縦並び）。管理者・閲覧者の双方が機器台帳一覧を経由せずに対象機器の個票を直接開けます。未適用入力がある場合は保存・破棄・キャンセルを確認し、確認中に対象機器が切り替わった場合は古い対象を開きません。
- **論理・物理ビューにおける機器名の視認性改善**：構成図上の機器名を通常幅で 13px に変更し、末尾の省略記号（`…`）を表示せずクリップする表示に改めました。機器名にポインターを重ねると全文をツールチップで確認でき、IP・状態表示および狭幅時の 11px 指定は維持されます。

## アップデート手順（v1.5.1 からの更新）

Netarium v1.5.0 および v1.5.1（DB スキーマ 23）から v1.5.2 への更新では DB スキーマ変更は発生しません。
v1.4.0（DB スキーマ 22）以前から更新する場合は、更新後の初回起動時にデータベーススキーマが 23 へ自動移行されます。

### 1. 更新前の完全バックアップ取得

作業前に、停止型完全バックアップを取得して外部へ保管してください。

- **Windows / IIS 環境**：管理者 PowerShell で `scripts/backup-full.ps1` を実行します。
- **Docker 環境**：`bash scripts/docker-backup.sh` を実行します。

### 2. プログラムの更新

環境に応じた手順で更新を実施します。

- **Windows / IIS 環境**：
  新バージョンの配布資材を展開し、管理者 PowerShell で `scripts/update.ps1` を実行します。手順と前提条件は [更新・ロールバックガイド](update.md) を参照してください。
- **Docker 環境**：
  ソースビルド構成では最新資材を取得して `bash scripts/docker-update.sh` を実行します。事前ビルド済みイメージ構成では、対象リリースの公開状況を GitHub Releases および GitHub Packages で確認した上で `compose.image.yaml` のイメージタグ（`ghcr.io/lgug-jp/netarium:1.5.2`）を指定し、`bash scripts/docker-update.sh -f compose.image.yaml` を実行します。手順は [Docker 配備・運用ガイド](deployment-docker.md#7-更新ロールバック手順) を参照してください。

## 互換性と運用の注意点

- **DB スキーマとバックアップ形式**：DB スキーマは `23`、バックアップ形式は Web 構成情報 ZIP（`netarium-config` 形式 1）および停止型完全バックアップ ZIP（`netarium-full` 形式 1）のまま変更ありません。
- **バックアップ復元互換性**：
  - **順方向復元（旧版 → v1.5.2）**：同一 MAJOR 内の過去正式版（`v1.0.0`〜`v1.5.1`、スキーマ 11〜23）で取得された両形式のバックアップ ZIP を v1.5.2 環境へ復元できます。
  - **逆方向復元（v1.5.2 → v1.5.1 以前）の拒否**：`BackupCompatibilityPolicy` により、v1.5.2 で取得したバックアップ ZIP は同一スキーマ 23 であっても v1.5.1 以前の環境へ復元できません（前段検査で拒否されます）。
- **旧バージョンへの切り戻し（ロールバック）制約**：v1.5.1 等へ切り戻す場合は、更新直前に取得したスナップショットからプログラムまたは Docker イメージ・DB・画像・環境設定を一括で復元してください。
- **完全バックアップ ZIP の対象外データ**：環境設定ファイル（`config/app.php`、`.env` など）、Web サーバーログ、SSL/TLS 証明書等は停止型完全バックアップ ZIP に含まれません。サーバー管理者側で別途保全してください。

# Netarium管理者ガイド

Netarium `1.0.0` の画面操作、利用者管理、管理者アカウントの復旧手順です。サーバーの新規配備は[配備ガイド](deployment.md)、更新・ロールバックは[更新ガイド](update.md)、バックアップ保管・全損復旧・撤去は[運用ガイド](operations.md)を参照してください。

日常操作は画面の「ヘルプ」から[ブラウザ内利用ガイド](../public/help.html)を参照してください。操作キャプチャをクリック、またはTabで選んでEnterを押すと原寸へ拡大できます。右パネル・機器個票の「Ping結果について」は共通の結果説明を開きます。NGを機器停止と断定せず、ICMP応答設定・ファイアウォール・経路も確認してください。

## 導入前の確認

サーバー管理者が[配備ガイドの前提条件](deployment.md#前提条件)に従ってIIS・PHP・SQLite、公開範囲、ACL、アップロード上限、Pingの実行条件を設定し、[CLI確認](deployment.md#cli確認)を完了したことを確認します。[セキュリティ確認](deployment.md#セキュリティ確認)は、初期管理者を作成した後に行います。HTTPSを原則とし、インターネットに到達可能な本番環境では必須です。閉域・隔離でHTTPを選ぶ場合は[許容条件](deployment.md#http運用の許容条件と記録202)を管理者が記録・承認し、接続元制限を維持します。

## 初回起動

サーバー側の初回配備は[配備ガイド](deployment.md)、自動setupを使用しない場合は[手動配備・全損復旧ガイド](deployment-manual.md)に従います。管理者はサービスFQDN・確認先URLに加え、公開前に発行した一回限りの初期登録用秘密をサーバーのローカル管理者から承認済みの安全な経路で受け取ります。秘密はログ、URL、PowerShell transcript、チャット履歴へ残しません。

1. 承認されたサービスURL（原則`https://<サービスFQDN>/login.php`、許容条件を記録した環境ではHTTP）へアクセスします。
2. 利用者が未登録の場合は`setup.php`へリダイレクトされます。
3. 初期登録用秘密、初期管理者のユーザー名とパスワードを入力します。秘密はフォームへ入力し、URLには含めません。ユーザー名は3〜50文字の半角英数字、`_`、`-`、`.`、新規パスワードは12～128文字（Unicodeコードポイント）、UTF-8最大512バイトです。英大文字・英小文字・数字・記号の組み合わせは必須ではありません。この条件は利用者登録・本人変更・管理者再設定・復旧CLIで共通です。成功画面を確認した直後、ローカル管理者が秘密の発行ファイルと受渡し用コピーを削除します。
4. ログイン後、ビュー作成、機器保存、Ping、CSV、図面、バックアップを確認します。
5. `scripts/verify-security.ps1`を実行し、`setup.php`がログイン画面への302または404になったこと、`data/`などの非公開パスが403または404になったことを確認します。

初期設定ページを手動で削除する運用は採用しません。DBに利用者が存在するか、初期登録完了が記録されていると初期設定は閉じます。登録に成功すると秘密の照合用SHA-256はDBから消去されます。登録失敗時は入力やサーバー環境を修正して同じ秘密で再試行します。紛失・漏えいの疑い・発行失敗時はサーバー管理者が[明示的に再発行](deployment.md#初期登録用秘密の再発行)し、新しい秘密を渡します。setup再実行による再発行はありません。登録済みの管理者復旧には下記の`recover-admin.php`を使用します。図面は認証済みの`floor_plan.php`経由で取得します。

文字数はUnicodeコードポイント単位で数えます。結合文字や複数の文字からなる絵文字は、見た目が1文字でも複数文字として数える場合があります。日本語・空白・記号・絵文字を使用できます。NUL・不正Unicodeは拒否します。前後の空白の除去、正規化、切り捨ては行わないため、設定時と同じ内容で入力してください。新規設定はArgon2idで保存し、非対応PHPではbcryptへ代替しません。ログインや変更時の現在値には新規設定条件を再適用しません。旧bcryptの照合は移行期間だけ許可しますが、ログイン成功だけでは移行しません。[アーキテクチャ](architecture.md#認証と権限)と[運用ガイドの移行手順](operations.md#パスワードの明示移行169)を参照してください。

ログインのユーザー名は、前後空白の除去後に3〜50文字の半角英数字、`_`、`-`、`.`で検査します。不適合な値も通常の認証失敗と同じ表示となり、ユーザー名欄は空になります。不適合入力はログイン試行制限・横断失敗集計へ保存せず、監査には入力本体を含めない認証失敗だけを記録します。適合する名前はユーザー名単位で5回失敗すると300秒ロックし、ログイン成功時に失敗記録を解除します。別セッションでもロックを維持します。

### 仮パスワードの発行と初回本人変更

管理者が新規登録・再設定した利用者と、復旧CLIで作成・再設定したadminは、仮パスワードでログインした後に初回変更画面へ進みます。本人だけが知る別の値へ変更するまで、通常画面・編集API・管理API・画像は利用できません。変更後はログアウトするため、新値で再ログインしてください。管理者自身の再設定にも適用します。本人が初期setupで設定した初期adminと、機能追加前からの既存利用者は一律の変更強制対象にしません。

仮パスワードは利用者ごとに異なる十分に長い値を発行し、組織が承認した別の安全な経路で本人確認後に渡してください。ユーザー名と秘密を同じ公開連絡・Issue・チャット履歴へ残さず、受渡し期限と本人変更の完了確認を管理します。仮パスワードには自動失効期限がないため、未受領・未利用のアカウントは運用判断で停止し、漏えいの疑いがある場合は別の値へ再設定します。

全設定経路で標準 PWDB 3,000 件、管理者が任意登録した追加辞書、全体反復、ユーザー名・Netarium から推測しやすい値を拒否します。単語を含むだけの長い passphrase は拒否しません。拒否された値やハッシュを運用記録に保存せず、別の長い秘密を設定してください。「パスワード安全性データを確認できない」と表示されたら、標準辞書の固定検証を無効化せず、サーバー管理者が配備・読取 ACL・本文と manifest の破損を確認して `check-install.php` を実行します。追加辞書の導入・更新・解除・復旧は[運用手順](operations.md#任意追加辞書)を参照してください。

本人変更の現在値は、利用者単位で5回失敗すると300秒制限されます。別ブラウザ・再ログインでも解除されません。時間経過を待つか、本人確認後に別adminが仮パスワードを再設定します。全adminが復旧できない場合は次節のCLIを使います。再設定・CLIはログイン制限と再認証制限を解除し、古いセッションを失効させます。

監査の`password_spray_suspected`は共有接続元から300秒内に5対象以上への失敗を検知した警告で、攻撃の確定ではありません。NAT／プロキシ・利用者の誤入力を確認し、IISログと接続元SHA-256を照合します。転送ヘッダーを信頼していないため、プロキシ経由の元端末は境界ログで確認してください。IP共有を理由に一律ロックせず、個別の本人確認・再設定・接続元制御を運用判断します。

## 権限と保存

- `admin`は機器、ビュー、接続、メモ、図面、CSV、品質診断、バックアップを管理し、Pingを実行できます。
- `viewer`は保存済み情報とPing結果を閲覧できます。Pingは実行できません。
- `admin`は上部「管理」→「利用者管理」から、利用者の登録、停止・再開、`admin`/`viewer`の変更、パスワード再設定を行えます。停止またはパスワード再設定を受けた利用者は、次回のページ/API/図面要求でセッションが失効します。
- 最後の有効な`admin`は停止または`viewer`への変更ができません。別の有効な`admin`を先に用意してください。
- 利用者メニューの「パスワード変更」では、本人の現在のパスワードを確認して変更します。変更後は再ログインが必要です。
- 台帳一覧は機器行を離れる時、個票、右側の機器詳細、接続情報とビュー設定は「適用」、配置はクリックやドラッグ終了で変更を確定し、保存を開始します。
項目移動や入力停止だけでは詳細入力を確定しません。
上部の「保存」は確定済み変更の即時送信や再試行用で、未適用入力は対象外です。
- サーバーの保守作業中は、API から専用の拒否応答（HTTP 404、`application/json`、`NETARIUM_MAINTENANCE_REJECTED`、`request_execution: "not_started"`）が返ります。
クライアントが専用契約を厳密に確認した場合に限り、この要求の PHP 保存処理は未実行として扱います。
画面には保守作業中である旨の警告が表示され、入力内容、保存中に行った後続の編集、図面設定、新規作成の仮 ID は保持（pending）されます。
保守状態が解除されても自動的な再送は行われません。
画面を再読み込みすると保持していた編集内容が破棄されるため、画面を再読み込みせず待機し、保守作業の終了後に上部の「保存」ボタンを押して明示的に保存を再開してください。
- 通信切断、応答未達、汎用的な 404 や 503 を含むサーバーエラー、JSON 形式不正など、確定成否が不明な場合は専用拒否とは区別して扱われます。
これらは未実行の証明にならないため、ステータスバーに「? 未確認」と「保存状態を確認」ボタンが表示されます。
利用者は「保存状態を確認」を押し、変更対象の最新状態から正常確定、再試行可能、競合のいずれかを判定します。
新規作成の ID 対応を確認できない場合は「未確認」のままです。
再送や現画面の再読み込みをせず、入力を保持したまま別画面の保存済み一覧と照合し、判断できなければ管理者へ引き継いでください。
- 認証の有効期限が切れた場合は、編集画面上の入力内容を保持したまま再認証案内バナーが表示されます。別タブでログイン画面を開いて再認証を行い、本画面を参照しながら新しい画面へ再入力してください（旧画面からの自動保存は行われません）。
- 認証状態を確認できない一時的なDBロックでは、要求を503で拒否しますが既存セッションは破棄しません。API・通常ページ・ログイン入口・画像配信も対象です。ロック解除後は元のセッションを使えます。利用者停止・パスワード変更・有効期限切れによる失効とは区別し、保存の成否が未確認の場合は先に「保存状態を確認」を実行してください。
- 未保存変更がある間は、Ping、CSV、復元、再読み込みなどが制限または確認対象になります。
- 機器属性は機器ごと、配置・接続・メモ・ビュー設定はビューごとに競合を検出します。競合対象とその関連変更は保留しますが、独立した別機器・別ビューは保存を続けられます。競合対象を自動上書きせず、必要な入力内容を控えてから個票・詳細画面やビュー管理の対象再読込で最新状態を確認します。全体を再読込する場合は無関係な未保存入力も破棄されます。CSV取込・復元などの全体操作は、別対象の変更とも競合する場合があります。
- 機器削除後に画像整理の未完了が案内された場合、機器の削除自体は保存済みです。削除を再送せず、管理者が監査ログ、画像ディレクトリの権限・使用中ファイル、画像GCの残りを確認してください。
稼働中の`<InstallRoot>\data\db\data.sqlite`をSQLiteツールなどで直接編集しないでください。同じSQLite DBをネットワーク共有から複数サーバで同時更新する構成も使用しません。

### adminの緊急復旧

全adminが停止、降格、またはパスワード不明となりログインできない場合だけ、サーバー管理者がアプリケーションサーバー上で次のCLIを実行します。通常の利用者管理でDBを直接編集しないでください。

```powershell
php C:\Netarium\app\scripts\recover-admin.php `
  --db="C:\Netarium\app\data\db\data.sqlite" `
  --username="recovery-admin"
```

`--db`を省略すると、`NETARIUM_STORAGE_DIR`、`config/app.php`、既定の`<InstallRoot>\data`から解決されます。CLIで新しい仮パスワードを2回入力すると、指定した利用者が存在する場合は`admin`として再有効化し、存在しない場合は新しい`admin`を作成します。復旧処理は操作前に監査ログへ事前記録され、成否が調査IDとともに記録されます。実行後は`login.php`へアクセスし、仮パスワードと異なる値へ本人変更して再ログインしてから、通常の利用者管理を行ってください。CLIはアプリケーションサーバー上でのみ実行し、DBとパスワードをバックアップやコマンド履歴へ出力しないでください。

復旧CLIの新規設定もArgon2idで保存します。入力は前後空白を含め保持し、対話入力の行末は入力を区切るためのCR/LFだけを除きます。`--password-file`はUTF-8ファイルの全内容を秘密として扱い、BOMや行末改行も除きません。ファイルを使う場合はBOMなし・末尾改行なしで作成してください。旧bcryptの現在値が拒否される移行終了後も、管理者再設定と緊急復旧CLIで新しい秘密へ移行できます。

ファイルが必要な場合は、サーバ管理者だけがアクセスできる一時領域に次のように作成します。通常は復旧CLIの対話入力を使用してください。秘密をコマンド引数・履歴へ直接書かず、ファイル使用後は組織の秘密情報廃棄手順に従って処分します。

```powershell
$passwordPath = 'C:\ProtectedTemp\recovery-password.txt'
$secret = Read-Host '新しいパスワード' -AsSecureString
$credential = New-Object System.Net.NetworkCredential('', $secret)
[System.IO.File]::WriteAllText($passwordPath, $credential.Password, (New-Object System.Text.UTF8Encoding($false)))
Remove-Variable secret, credential
```

## 日常の操作

### ビューと機器

上部バー「管理」→「ビュー管理」の「ビューを登録」で既定名の新しいビューを登録します。名前や種別などの変更は「適用」で確定し、自動保存します。ビューを削除すると、そのビューの配置・接続・メモは削除されますが、機器台帳の機器は削除されません。

表示するビューは上部バーのビュー検索欄で選びます。クリックすると全ビューを表示し、ビュー名・施設・フロア・種別で絞り込めます。空白で区切った複数の語はすべて一致する候補を表示します。候補をクリックするか、↑／↓とEnterで切り替えます。Escまたはフォーカス移動で選ばずに閉じると、現在のビュー名に戻ります。ここへ入力した文字はビュー名として保存されません。機器・接続の未適用入力がある場合は、切替前に確認します。
ビュー検索欄の右隣にあるリンクアイコンから、現在のビューの永続 ID を含む直接リンクをクリップボードへコピーできます。自動コピーが制限される環境では、手動コピー用の URL ポップオーバーを表示します。未認証状態で直接リンクを開いた場合は、ログイン画面や初回パスワード変更画面を経て、指定されたビューへ安全に復帰します。

フロア図面を登録する場合は、ビュー管理で種別に「物理・フロア配置図」を選び、「適用」を押して保存します。登録と保存が完了すると種別欄の下にある「フロア図面」ボタンが有効になり、押すと対象のビューへ切り替え、ビュー管理を閉じて図面管理を開きます。未適用の入力がある場合や保存処理中、データの競合がある間はボタンが無効化され、横に理由が表示されます。

図面管理はサムネイルとファイル情報を表示し、登録・差し替え・削除・表示切替を扱います。「図面を調整」で管理画面を閉じ、Canvas上で本体をドラッグして移動、四隅のハンドルで縦横比を保った拡大縮小（5〜200%）ができます。不透明度は上部ツールバーで10%（薄い）〜100%（不透明）へ変更します。ホイールやフッターはCanvas自体の表示倍率を変え、図面のサイズとは独立しています。

図面にフォーカスして矢印キーで1座標単位、Shift併用で10単位移動できます。四隅にフォーカスした場合は上・右で1%拡大、下・左で1%縮小、Shift併用で10%変更します。「位置・サイズをリセット」は確認後、原点（0, 0）と100%へ戻し、不透明度と表示状態は保持します。非表示の図面は調整中だけ一時表示します。

移動・リサイズ・不透明度・表示切替は操作の確定ごとに自動保存します。「完了」は調整終了だけを意味し、管理画面は再表示しません。Escは操作中の移動・リサイズだけを取り消し、操作中でなければ調整を終了します。確定済みの値は戻しません。失敗時は値を保持し、フッターで状態を確認してください。「保存」で再試行、未確認時は「保存状態を確認」、競合時は内容を控えてビュー管理で最新データを再読込します。

調整を開始せず図面管理を×またはEscで閉じた場合は、左「図面」からならCanvasへ、ビュー管理からなら対象ビューの管理画面へ戻ります。閉じる操作で確定済みの設定は戻しません。差し替え時も位置・サイズ・不透明度・表示状態を引き継ぎます。縦横比の異なる画像では表示領域が変わるため、必要に応じて「図面を調整」を使ってください。

左操作パレットの「配置」で配置モードを開始します。「新規機器」タブで機器種別を選び、キャンバスの空白をクリックすると、その位置へ機器を登録・配置できます。同じ種別を続けて配置でき、配置ごとに機器情報パネルは開きません。Escまたは左の「選択」で終了し、「接続」へ切り替えると配置モードは終了します。配置中もホイールでズーム、空白ドラッグでパンを操作できます。

「未配置」タブでは「このビューに未配置」と「全ビュー未配置」を切り替え、機器を選択して配置キューへ追加します。キャンバスをクリックするたびに「次」の機器を1台ずつ配置します。台帳で機器を選択して「ビューに配置」を押す場合や、データ品質診断の「配置する」も、即座に配置せずキューへ引き継ぎます。ダッシュボードの「未配置」は、全ビュー未配置の機器に絞った台帳を開きます。「条件を解除」で通常の一覧へ戻れます。個票には配置ボタンを設けず、台帳からの配置導線を使用します。キューへの追加だけでは配置は確定しません。配置先をクリックして確定すると自動保存します。

機器の詳細は「選択」で対象をクリックして編集します。右側の機器情報パネルは「基本情報／設置情報／機器・資産情報／管理・保守情報／補足・状態」の五分類で構成され、名称、IPアドレス、施設、フロア、設置場所、メーカー、型番、管理番号、シリアル番号、MACアドレス、備考を入力できます。「適用」で複数項目をまとめて検証・確定し、自動保存を開始します。保存中も次の入力を続けられます。別の機器や接続へ切り替える、またはパネルを閉じる時に未適用入力があれば、「適用」「変更を取り消す」「編集を続ける」から選びます。「変更を取り消す」は未適用入力だけを最後の確定値へ戻し、保存済みの変更を取り消しません。機器情報パネル上部および台帳個票ヘッダーのリンクアイコンからも、対象機器の直接リンクをコピーできます。

個票と右パネルでは、一度の「適用」で検出した入力エラーを各項目の近くに表示します。施設・フロア・設置場所は台帳でも既存値の候補を利用できます。候補を選ばず新しい値を自由入力することも可能です。

台帳で機器を1台以上選択し、「一括編集」から施設、フロア、設置場所、担当部署、保守ベンダー、保守期限、メーカー、型番、導入年月日、接続方式、ポートを共通の値へ変更できます（管理者のみ）。日付形式は個別編集と同じYYYY-MMまたはYYYY-MM-DDです。「変更する」にチェックした項目だけを対象とし、チェックして空欄にすると値を消去します。対象台数と変更内容を確認して適用すると、全台を検証してから変更し、自動保存します。

接続方式は未設定／HTTP／HTTPS／SSH、ポートは1〜65535の整数または空欄で指定します。接続方式が未設定の機器にポートだけを設定する操作は拒否します。接続方式を未設定に戻すとき、既存のポートがあればポートも変更対象にして空欄にしてください。未選択項目を自動的に消去することはありません。確認画面では変更前を控えめに、変更後を青で強調し、「空欄にする」を警告色で区別します。

対象は開始時の選択IDで固定し、フィルタによる表示外の選択も含めます。適用後は選択を解除します。施設・フロアを変更してもビューの配置先や座標は変更せず、配置済みの対象がある場合は確認画面へ注意を表示します。未適用の個別入力がある対象機器は、先に適用または破棄してください。開始時に個票を閉じ、確認中の属性変更や競合がある場合は一括適用を拒否します。

設置情報グループでは、X/Y座標の数値入力と「座標を適用」ボタンにより、マウスを使わずキーボードのみで配置位置を編集することも可能です。

機器をビューから外す操作は、現在のビューの配置と関連接続だけを削除します。上部バーの「台帳」ボタンから完全削除すると、機器、全ビューの配置、関連接続を削除します。完全削除の前にはバックアップを取得してください。

キャンバスの表示倍率はフッター右端の操作（「全体」「−」「現在倍率」「＋」）で調整できます。現在倍率を押すと標準の100%へ戻ります。右の情報パネルを開閉しても操作位置は変わりません。初期表示と「100%」では原点を左上端に置き、配置不可領域用の余白を設けません。「全体」は原点を含む範囲を左上端から収め、100%を超えて自動拡大しません。floorビューは表示中の図面全体を対象とします。保存済みの表示位置・倍率はビューを開き直した時に優先復元します。以前の表示位置で配置不可領域が広く見える場合は、現在倍率または「全体」で位置を調整してください。

フッター左側には現在ビューの機器・接続・選択件数と保存状態を表示します。「未確認」の場合だけ、保存状態の左隣に「保存状態を確認」が表示されます。中央には読み込みなどの処理状況、Ping結果と「結果を表示」、短時間の案内を表示します。長文にポインターを重ねると全文を確認できます。狭い画面では左・中央を横スクロールでき、Tabでも操作ボタンへ移動できます。台帳などのモーダルを開いている間、背後のCanvasへのズーム操作は非表示になります。

### ラックビューの操作と機器搭載

上部バー「管理」→「ビュー管理」で「＋ ラック図」を押すと、初期設定のラックを作成して自動保存します。
幅の狭い画面では「登録する種別」で「ラック搭載図」を選択して「ビューを登録」を押します。
ビュー管理モーダルのツールバーは操作ボタンと種別選択の高さを 36 px で統一しており、種別選択欄には通常ビューと相互に変更できない旨の案内を表示します。
その後、名称や総 U 数を入力し、「適用」で確定します。
ビュー名がラック名に対応し、既存の施設、フロア、表示順、備考に加えて、ラック固有の「設置場所」（150 文字以内）と「総 U 数」（1 〜 60 の整数、初期値 42）を設定します。
総 U 数の変更時、既存の搭載機器の U 範囲を切り捨てるような縮小は拒否されます。
通常ビュー（論理構成図、フロア配置図）とラックビューの相互変換は行えません。
種別の変更によって物理搭載情報が失われる経路を防ぐため、種別変更の操作は禁止しています。
搭載機器が 1 台でも残っているラックビューは削除できません。
ラックを削除する場合は、先に搭載機器を取り外す必要があります。
ラックビューを複製した場合は、名称、施設、フロア、総 U 数、設置場所の設定とビュー注釈を引き継ぎ、機器の搭載情報を含まないラックビューを作成します（UI のボタンは「複製」です）。

ラック名は既存のビュー切替欄で確認できます。
ラック内のヘッダーは施設、フロア、設置場所を簡潔に表示し、上部の余白を縮小して搭載図を優先して表示します。
前面と背面を常時表示し、各面に U 番号を付けます。
幅の広い画面では横並びで表示し、幅の狭い画面では縦並びで表示します。
U 番号は最下段を 1 U とし、上方向に向かって昇順で並びます（42 U ラックでは最上段が 42 U、最下段が 1 U です）。
前面と背面は同一の U 番号と縮尺に揃えて描画します。
各面の各 U は左右 2 つのスロット（左半分、右半分）で構成され、全幅機器は両スロットにまたがって表示されます。
ラックの稼働状況として、「空き U（左右両スロットが空き）」「半空き U（片側スロットのみ使用）」「使用中 U（両スロット使用）」の各件数を前面と背面それぞれ独立して集計、表示します。
前面と背面の U 数を合算して「ラックの空き U」として誤認させる表示は行いません。
検索、配置先、共有リンクから搭載機器へ移動すると、該当面へスクロールします。
左パレットの「Ping」では、ラックビューで選択中の搭載機器も実機器 ID で対象に含まれます。
左パレットのワークスペースナビゲーション（機器一覧）でも現在ラックに搭載されている機器を実機器 ID で重複なく表示し、選択すると対象の搭載位置へフォーカスしてスクロールします。
ラックビューでは、左パレットの XY 配置、接続線編集、フロア図面管理、メモ配置を無効化し、理由をツールチップで表示します。
メモはラック右側の上段、中段、下段の 3 領域で直接編集します。
既存メモは本文、文字色、背景色、文字サイズ、保存座標を変えず、すべて上段に表示します。
各領域の空欄へ本文を入力すると新しいメモを作成し、空白だけの入力では作成しません。
保存済みメモの右上に表示されるゴミ箱ボタンから確認後に個別削除できます。
入力欄からフォーカスを外すと自動保存します。
幅の狭い画面でもメモ欄はラックの右側に維持され、画面の横スクロールで確認できます。
メモ欄の高さはラック本体の表示高さや拡大縮小に追従します。
3 領域はラックの表示高さを概ね 3 分割し、総 U 数を変更しても所属する領域は変わりません。
低いラックではメモ欄側をスクロールし、ラック本体や U 目盛りの高さは引き伸ばしません。
印刷では領域順と見出しを付け、複数メモを右側へ全件表示します。
ラック上での自由なドラッグ配置やリサイズは行いません。
フッターで拡大縮小すると、ラックとメモの表示倍率が変わります。搭載位置やメモの保存座標は変更しません。

ラックへの機器搭載には、既存の機器台帳に登録済みの機器 ID をそのまま利用します。
ラック専用の機器マスタを新設せず、論理構成図やフロア配置図への配置と物理ラックへの搭載は独立して共存します。
1 台の物理機器が搭載できるラック位置は、システム全体で最大 1 箇所です。
搭載位置の範囲選択は、空きスロットをクリックして 1 U を選択するほか、PC では同じ面のセルをドラッグして連続した U 範囲を選択できます。
左右の列をまたいでドラッグした場合は全幅（`full`）として選択されます。
ドラッグ中は画面中央上部のキャンバスツールバーに選択範囲（面、U 範囲、スロット）が表示され、「搭載」でダイアログを開き、「キャンセル」で選択を取り消します。1 U のクリック時はそのまま搭載ダイアログが開きます。
タッチ操作では開始セルと終了セルを順にタップし、キーボードでは空きセルで Enter キーを押して開始し、終了セルで Enter キーを押すことで範囲を指定できます。
既に搭載されている機器ブロックをドラッグすると、占有 U 数と搭載面を保ったまま開始 U の移動をプレビューします。ハーフ幅機器は左右スロット（左半分／右半分）の移動や上下・左右の斜め移動も行えます（全幅機器は全幅を維持します）。
他の搭載機器との衝突や U 範囲外への移動は無効表示となって確定されず、有効な位置でドロップした時のみ位置を更新して保存します。
別ラックへの移設や搭載面の変更は、後述の機器詳細パネルまたは搭載ダイアログで行います。
搭載ダイアログでは、名称または IP アドレスを 1 つの検索欄へ入力し、候補をクリックするか上下キーと Enter で選択します。
候補には機器種別、登録済み IP、現在のラックと搭載位置を表示します。検索内容を変更すると選択を解除し、候補一覧が開いているときの Escape は一覧だけを閉じます。
空きセルから開いた場合は搭載先ラックを固定し、選択した面、左右、開始 U、占有 U 数を引き継ぎます。
面と横幅、開始 U と占有 U 数は PC では 2 列、狭い画面では 1 列で表示し、入力に合わせて範囲概要と衝突箇所を更新します。不正な範囲は保存できません。
「新しい機器を登録」へ切り替えると、既存の機器種別ピッカーで種別を選択でき、機器台帳への新規登録とラックへの搭載を同一バッチで保存し、既存の詳細パネルで名称などを編集できます。
ラックへ機器を搭載、移設しても、機器台帳に登録済みの施設、フロア、設置場所を自動で上書きすることはありません。
搭載機器は、機器種別に応じた色、アイコン、機器名に加え、設定済みの IP アドレスと Ping 監視状態（OK、NG、確認中）が表示されます（IP 未設定時の空欄は表示しません）。
シングルクリックすると機器を選択して右側に詳細パネルを開き、ダブルクリックすると搭載位置変更ダイアログを開きます（閲覧権限ではダイアログは開きません）。
ドラッグ操作直後の誤発火は抑止されます。ポインターを重ねると名称、IP、監視状態、搭載面、U 範囲、横幅スロットをツールチップで確認できます。
ラック画面の配色は共通のスタイル定義（CSS 変数）に統合されています。
ラックビューでは右側の機器詳細パネルが重ね表示（オーバーレイ）となり、パネルの開閉によってラック図やメモの表示幅や倍率は変わりません。背面ラックやメモが隠れる場合は横スクロールで確認できます。
選択中の機器は枠線で識別され、選択状態で Delete キーを押すとラックから取り外せます。取り外し対象はラック搭載情報のみであり、機器台帳、IP、通常構成図の配置、接続情報は削除されません。テキスト入力中や閲覧権限では発動しません。

搭載面の選択肢は「前面（`front`）」「背面（`rear`）」です。
既存データやバックアップにある `face=both` は、両面全幅を占有する旧形式として表示・保存・復元できます。
搭載位置の編集画面では「前面・全幅・奥行き全体」を初期値にし、旧形式から変換される旨を表示します。
設定を保存した場合だけ選択した前面／背面と奥行きへ変換し、キャンセルや他の属性の保存では `both` を保持します。
奥行き全体・全幅のまま保存すれば、元の両面の物理占有を維持します。
開始 U（`start_u`）は機器が占有する最下段の正の整数 U であり、占有 U 数（`height_u`）は正の整数です。
横幅位置（`width_slot`）は「全幅（`full`）」「左半分（`left`）」「右半分（`right`）」の 3 択です。
データの保存基準は「ラック前面から見た物理的な左右」で統一されています。
背面図では背面から見た向きに合わせて左右スロットを反転して表示し、背面 UI で入力した左右位置は保存前にクライアントが前面基準へ換算します。
奥行き（`depth`）は「半分（`half`、既定）」と「全体（`full`）」から選択します。
半分は取り付け面だけ、全体は反対面の同じ物理左右と全 U 範囲も占有します。
反対面から塞がれたスロットは原因機器名付きのグレー表示となり、範囲選択や搭載には使用できません。
空き U、半空き U、使用中 U とダッシュボードの面別占有率にも使用不可枠を含めますが、搭載台数は実機器 ID の一意件数のままです。

U の衝突判定は「ラック × 搭載面 × U 番号 × 横幅スロット」の単位で行われ、重複、範囲外、存在しない機器、同一機器の二重搭載は保存前およびサーバー保存時の両方で拒否されます。
ハーフ幅であれば同一面の同一 U に左右 2 台の異なる機器を搭載できます。
前面と背面の同じ物理スロット、同じ U には、双方が「半分」の場合だけ別々の機器を搭載できます。
「全体」が半幅なら、反対面のもう一方の物理半幅は使用できます。前後占有は従来どおり両面全幅を使用します。
これは簡易占有モデルであり、実寸、棚板、金具、配線、放熱の物理的な干渉は保証しません。
小型スイッチや UPS、ONU は既存の機器種別で登録します。
ONU・メディアコンバーター等は原則「その他」、小型スイッチは L2／L3 を選び、IP は空欄でも登録できます。

搭載機器を選択すると右側の機器詳細パネル（プロパティパネル）に「ラック搭載位置」セクションが表示され、面、開始 U、高さ、横幅、奥行きの変更や「ラックから取り外し」を行えます。
このセクションは補助情報や監視状態の後に配置され、適用ボタンの前に表示されます。
折り畳み（開閉）が可能で、見出し横には「ラック名 / U範囲」（例: `ラックA / 20U`、`サーバラック01 / 10〜12U`）が 1 行で簡潔に表示されます。長いラック名は省略表示され、ツールチップで全文を確認できます。展開すると面や左右位置を含む詳細が表示されます。
「搭載位置を変更・移設」から開くと現在のラックを初期選択し、別ラックも選択できます。
現在位置と変更先を分けて表示し、保存ボタンは同じラック内では「搭載位置を変更」、別ラックでは「ラックへ移設」になります。
別ラックに搭載済みの機器を移設する場合だけ、機器名と「移設元 → 移設先」の位置関係、元ラックの搭載位置が解除される注釈を最終確認します。
「キャンセル」で入力へ戻り、「移設を確定」で保存します。同一ラック内の変更、新規搭載、取り外しにはこの追加確認はありません。
確認中に機器や搭載位置、権限、元先のラックの保存世代が変わった場合は、条件を確認し直してください。
内容が画面に収まらない場合は入力部分をスクロールし、下部の保存とキャンセルは表示したまま利用できます。
「取り外し」はラックの搭載レコードのみを削除し、機器台帳本体や通常ビュー上の配置、接続は削除しません。
機器台帳から機器本体を完全に削除した場合のみ、連動してラック搭載レコードも削除されます。
また、ラック間の移設は元ラックと移設先ラックの双方の整合性とリビジョンを検証し、単一トランザクションで確定します。

ダッシュボードや機器台帳の「未配置」判定において、通常ビューの XY 配置だけでなく、ラック搭載も「配置済み」として共通に判定します。
機器台帳の「表示ビュー」および「機器の配置先」にラックビューを含めて表示します。
ラックへ機器を搭載、移設したことによって、機器台帳の既存「施設」「フロア」「設置場所」が自動的に上書きされることはありません。

#### 棚板と小型機器

ラックビューの左サイドバーでは「配置」が「棚板」に切り替わります。
「棚板」を押して空き U をクリック、または範囲選択すると、面・開始 U・占有 U 数を引き継いだ設定画面を開きます。
棚板名と位置、奥行き（半分／全体）を確認して追加します。

### 機器の検索・管理接続・機器間の接続

検索欄では名称、IPアドレス、施設、型番などを検索できます。配置済みの機器は対象ビューへ移動し、未配置の機器は台帳で表示します。

「機器へ接続」では機器に保存したHTTP、HTTPS、SSHの方式とポートを初期表示します。ポートは1から65535の整数だけを使用します。接続確認画面での一時変更は機器情報へ保存されません。HTTPとHTTPSは新しいタブで開き、SSHは端末側のURLスキーム関連付けが必要です。

機器間の接続は同一ビュー内で作成します。左操作パレットの「接続」を押すと補助パネルが開き、キャンバスで接続元と接続先を順に選ぶと自動保存します。「接続元を固定して連続作成」で同じ接続元から続けて作成できます。「接続元を選び直す」は選択と固定状態を解除します。×・Esc・別モードやビューへの切替で接続モードを終了しても、作成済みの接続は取り消しません。「接続一覧」は接続の選択・表示位置への移動に使用します。ラベル、系統、ポート、VLAN、備考は「適用」で確定して自動保存します。選択中の接続はDeleteキーからも削除確認を開けます。文字入力中やモーダル操作中には発火せず、閲覧者は削除できません。自動経路とラベル位置は配置座標から計算されます。通常規模では機器や他の接続との重なりを減らし、1ビューの接続が500件を超える場合は表示速度を優先して固定間隔で経路をずらします。経路の手動調整は接続情報の「経路調整」から開始します。

接続情報はラベル、系統、VLAN、接続元、接続先、経路、備考の順に表示します。接続元・接続先には機器名とIPアドレス、ポートを同じ枠内に表示します。間にある「↑↓入れ替え」は機器と入力中のポートをセットで交換し、「適用」で確定して自動保存します。「変更を取り消す」は未適用の入れ替えと入力だけを破棄して前回適用した値に戻し、適用済みの変更は取り消しません。

経路調整はドラッグを離した時、矢印キー、折れ追加・削除、自動経路への復帰で確定して自動保存します。保存中も次の操作を続けられます。同じビューで保存が競合した場合は未確定のドラッグを破棄して調整を終了し、確定済みの未保存変更を保持します。自動上書きはしません。「競合したビューを再読込」で破棄を確認すると、そのビューの未保存変更と未適用入力を捨て、最新の経路で調整を再開できます。独立した別ビューの変更は保持・保存します。閲覧者は保存済みの手動経路を表示できますが、編集・保存はできません。

## Pingと品質診断

Pingは常時監視ではなく、管理者がWindowsの`ping.exe`で行う手動疎通確認です。保存済みIPアドレスを対象に、既定ではプライベートIPv4だけを許可し、1回あたり最大100件、個別タイムアウトは1,000ミリ秒です。直列で実行し、全体の120秒のソフト期限を対象機器間で判定します。期限を超えた場合は残りをスキップし、完了済みの結果とスキップ理由をDBへ保存します。実行中の1台は中断しません。

上部「台帳」で対象をチェックし、「Ping（件数）」を押します。表示中の全件ではなく、表示外も含むチェック済み機器だけが対象です。0件では実行できません。管理メニューの「全機器Ping」は廃止し、左「Ping」による現在ビューの選択機器の確認は維持します。

台帳には選択件数と表示外件数を表示します。Ping実行中はフッターで対象件数・経過時間を確認できます。完了後はフッターの件数と「結果を表示」、または台帳の「結果を表示」から「Ping実行結果」を開きます。結果は台帳内へ展開せず、モーダルを自動で開くこともありません。結果画面は右上の「×」またはEscキーで閉じます。閉じても台帳の選択・検索・フィルター・スクロール位置・監視状態を保持します。

結果画面はOK／NG／タイムアウト／スキップ／未確認を集計し、機器名と実行先IPを同じ欄に、結果・取得済みの応答時間・詳細への操作を一覧で表示します。理由は「詳細」を押して展開します。「失敗のみ」はNGとタイムアウト、「成功のみ」はOKが対象です。スキップ・未確認は「すべて」で確認します。台帳の状態「NG」はタイムアウトを含み、結果画面のNGとタイムアウトの合計に対応します。IPなし・形式不正・許可外IPはスキップし、台帳の状態は「未確認」です。API要求が失敗した場合は処理エラーと今回の全対象の「未確認」を表示し、直前の監視状態は保持します。

一覧上部の「CSVダウンロード」は表示フィルターにかかわらず今回の全件を出力します。実行日時・機器名・IPアドレス・結果・応答時間(ms)・エラー概要を、BOM付きUTF-8で出力し、数式として扱われる文字列には先頭アポストロフィを付けます。ファイル名は実行開始時のローカル日時による`ping_yyyymmdd_hhmmss.csv`です。直近1回の結果は画面を再読み込みするまで保持し、新しいPingを開始すると置き換わります。履歴DBやサーバーへの永続ログは追加していません。

「監視詳細」で保存済みの最終確認・応答時間・エラーを確認できます。エラー欄の「詳細」を押すと全文を開閉できます。基本の状態表記はOK・NG・未確認、実行中は確認中です。Canvasはアイコン枠ではなく機器ノード外枠を状態色で表示し、選択や接続元の強調と区別します。Canvasと一覧の機器行のtooltip・読み上げ名には、取得済みの応答時間・最終確認・エラーを残します。確認中のtooltipは過去の結果を含めません。NGだけ再実行するときは「選択を解除」→状態「NG」→再チェック→「Ping」の順に操作します。未適用入力・未保存変更・保存処理中は、先に適用・保存を完了してください。

Ping実行中はユーザー横断で排他制御が行われ、同時に実行できるPingはシステム全体で1件のみです。別の利用者がPingを実行中の場合は即時拒否（409）されます。また、Ping実行中に他の利用者によって機器のIPアドレスや構成が保存・変更された場合、旧IPの誤判定結果を上書きしないよう、DBトランザクション確定時にデータリビジョンを再照合し、相違がある場合は結果を破棄して再読み込みを促すエラー（409）を返します。

実行中のフッター表示は「Ping実行中: ○件・経過○秒」です。現在のAPIは途中の完了件数を返さないため、完了台数の進捗率は表示しません。保存状態はフッター左側で確認します。通信切断やブラウザ終了が発生した場合、サーバー側での処理完了や保存状態は保証されないため、通信復旧後に画面を再読み込みして監視結果を確認してください。

Ping成功はHTTP、HTTPS、SSHなどのサービス正常性を保証しません。ICMP拒否、ファイアウォール、経路により、稼働中の機器でもNGになる場合があります。
上部バーの「ダッシュボード」では、「運用状況」と「資産・保守」の 2 タブでシステム状態を確認できます。
「運用状況」タブでは、日常の監視状態（OK／NG／未確認）、データ品質診断の問題件数、未配置機器などの主要 KPI を PC 向け 2 段（上段 4 枚・下段 3 枚）で確認できます。
「資産・保守」タブでは、施設別・フロア別・種別ごとの機器構成内訳と、保守期限の見通し（期限超過、残り 1 年以内、残り 1〜2 年、2 年超、期限未登録）を確認できます。
保守期限カードの件数（期限超過、残り 1 年以内、残り 1〜2 年）をクリックすると、機器台帳へ直接遷移して対象機器を絞り込み、保守期限順で表示します。台帳の一時的な保守管理列表示は保存済みの列設定を上書きしません。年月（YYYY-MM）のみ登録された保守期限は月末日として判定されます。
「資産・保守」は保守期限・機器内訳・ラック管理の順に並びます。
ダッシュボードは両タブで同じ外枠サイズを使い、詳細を開閉しても高さは変わりません。内容が多い場合はヘッダーとタブを残して内部をスクロールできます。
機器内訳には登録機器数と機器種別の分類数、ラック管理には登録ラック数と搭載機器数を、詳細の開閉にかかわらず表示します。
「内訳を見る」「ラック一覧を見る」をクリックするか、ボタンにフォーカスして Enter／Space を押すと、それぞれの詳細を独立して開閉できます。
機器内訳を展開すると、既存の施設別・施設とフロア別・機器種別別の内訳から台帳への絞り込みや「すべて表示」を利用できます。
一覧のラック名を選ぶと、そのラックビューへ移動します。施設・フロア・設置場所は登録がある場合だけ補助表示します。
搭載数は機器 ID ごとに集計し、前後面やハーフ幅の表示で重複させません。
ラックの行には前面・背面それぞれの空き U 数も表示します。空き U は、その面の左右両スロットが空いている U 数です。片側だけ空いている半空き U は含みません。
前面・背面の細い横棒は、それぞれ「占有スロット U 数 ÷（総 U 数 × 2）」を示します。全幅は 2 スロット、ハーフ幅は 1 スロット、前後占有は両面へ反映します。空き U 数とは基準が異なるため、棒の長さは空き U 数の単純な裏返しにはなりません。
機器やラックが未登録でもカードと 0 件の集計を表示します。「更新」で再集計し、ダッシュボードを開き直すと機器内訳とラック一覧の両方が閉じた状態に戻ります。
上部バー「管理」→「データ品質診断」では、参照不整合、重複、入力不足、未配置、監視状態、図面状態などを確認できます。修正後は保存して再診断します。ダッシュボードの基本集計は画面上のデータ、品質集計は保存済みDBを基準とするため、未保存変更がある場合は件数が異なることがあります。

## CSV、フロア図面、機器画像

CSV出力は保存済みの機器台帳全件を19列（保守接続情報を含む新形式）で出力します。CSV取込はUTF-8、最大2MiB、最大5,000データ行です。19列のヘッダーと列順を完全一致させる必要があり、旧13列CSVや未知の列を含むCSVはエラーとして拒否されます。エラーが1件でもある場合は取込を実行できません。検証結果を確認して「取込を実行」を押します。新形式CSVで空欄の項目は空値/NULLとして反映されます。

設置場所（`location`）は通常編集・CSV取込とも150文字以内です。日本語や補助漢字もUnicodeコードポイント単位で数えます。CSV出力は保存済みの値を切り詰めません。既存機器では、出力時の数式対策用アポストロフィを除いた値がDB既存値と一致する場合だけ、項目検証より先に元の値へ復元します。復元後の値が151文字以上の取込行は検証エラーとなり、取込を実行しても現行データは変更されません。新規行・既存値と一致しない行はアポストロフィを除去せず、その文字も含めて上限を検証します。

CSV取込で変更するのは機器台帳だけです。ビュー、配置、接続、図面、機器画像は変更されず、新規機器は未配置で登録されます。IPアドレスを変更すると監視状態は未確認に戻ります。

- フロア図面はPNG/JPEG、入力1枚30MiB以下・各辺7,000px以下・3,500万画素以下、最大100枚です。EXIF向き補正後に長辺4,096px以下へ自動縮小し、同形式・1枚10MiB以下の変換結果だけを保存します。小画像は拡大せず、PNG透過を保持します。原本は残らないため登録前に別途保管してください。管理画面の取り込み元名と保存形式・容量・寸法を確認します。差し替えは座標・倍率・不透明度・表示状態を保持しますが、保存寸法が変わった場合はCanvasの「図面を調整」で位置・サイズを確認してください。4,096px・JPEG品質95は初期採用値で、実スキャンの文字・細線の可読性は未確認です。
- 機器画像はPNGまたはJPEG、入力は1枚10MiB以下、各辺4,000px以下、総画素数1,200万以下です（1機器最大3枚）。EXIFメタデータを除去し、向き補正後に長辺2,048px以下へ縦横比を維持して縮小します。小さな画像は拡大せず、PNGの透過を保持します。アップロード原本は残りません。必要な原本は登録前に別途保管してください。画像に写った個人情報は除去されません。機器画像の登録・差替え・削除・順序変更は即時確定され、機器属性の下書きや別の機器・ビューの保存待ちを理由に禁止しません。新規機器は登録の保存完了を待ってください。画像操作は全体世代を検査するため、同時更新で競合が返った場合は最新状態を確認してください。
- 画像全体の件数・総量に対する一律上限（旧 108 ファイル／200 MiB）は撤去され、ディスク空き容量および任意の運用クォータで管理します。
1 機器最大 3 枚、写真保存 1 枚 10 MiB 以下、図面保存 1 枚 10 MiB 以下・最大 100 枚の安全上限は維持します。
画像アップロード専用 URL（`image_upload.php`）の受信上限は 31 MiB であり、超過時は HTTP 413（IIS 413.1）で拒否されます。
サーバー保守作業中は、この 413.1 より RequestFiltering による `.php` 拒否（IIS 404.7、専用 JSON 拒否）が優先されます。
なお、`public/web.config` には 404.13 のマッピングが保持されていますが、実環境での 404.13 実応答は未検証です。
- `data/uploads/floorplans`および`data/uploads/device_images`内のファイル名を変更・移動・削除しないでください。Web構成情報ZIPに画像実体は含まれず、画像ファイルの復旧には使えません。
- 新しい登録寸法制限は既存画像へ遡及しません。Web復元は既存画像を再変換せず、保存名・サイズ・MIME・寸法・SHA-256が一致する実体だけを参照します。

機器画像は右パネルまたは個票のサムネイルから拡大表示できます。「前の画像」「次の画像」で同じ機器の画像を一覧の表示順に切り替えます。先頭・末尾では該当ボタンを無効化し、1枚だけの場合は両方を無効化します。

## 接続系統とビュー内一覧

「管理 > 接続系統設定」で、全ビューに共通する系統の名称と色を追加・変更します。色は用意された8色から選びます。使用中の系統は削除できません。先に接続を別系統または「未設定」へ変更してください。閲覧者は名称・色・使用件数を確認できますが、変更できません。

接続を選択し、右の「接続情報」で系統を指定して「適用」します。未設定は従来の標準色です。設定した色は選択・hover・手動経路・交差表現でも維持され、印刷にも反映されます。

左「一覧」の「機器」は現在ビューに配置した機器だけを表示します。「台帳で開く」はダッシュボードからの条件付き起動と同様に前の検索条件を初期化し、台帳の「表示ビュー」に現在ビューを選んだ状態で開きます。表示ビューは追加・解除でき、キャンバスのビューは変わりません。上部「台帳」から通常起動する場合はビュー条件だけを解除し、他の条件を引き継ぎます。

台帳の表示ビュー、施設、フロア、状態、種別、IP登録、配置状態、保守期限の8項目は複数選択できます。同じ項目内はOR条件、項目間と検索はAND条件です。0選択の項目は「すべて」で、絞り込みません。表示ビューを複数選ぶと、選択したビューの配置の和集合に含まれる機器を重複なく表示します。同名ビューもIDで区別し、別の候補として選びます。

選択欄のボタンは0選択で「すべて」、1件で選択値のラベル、複数件で件数を表示します。開いた候補を押すと選択・解除し、一覧は開いたままです。キーボードでは矢印キーで移動、Home／Endで先頭／末尾へ移動し、Enter／Spaceで選択・解除します。Esc、Tab、フォーカス移動または外側クリックで閉じます。値ごとのチップの「×」でその値だけを解除し、検索チップの「×」で検索だけを解除します。「条件を解除」は検索と8項目をすべて解除します。

フィルター候補の選択と機器行のチェック選択は別の操作です。表示ビューの選択集合が変わった場合だけチェックを解除します。他の条件や検索の変更では表示外のチェックも残り、候補の再描画やID再採番で同じビュー集合を保持した場合もチェックを維持します。「条件を解除」はビュー条件を含む場合にチェックを解除します。チェックだけをすべて外す場合は「選択を解除」を使います。一括編集・Pingは表示外も含むチェック済み機器が対象なので、実行前に対象件数と表示外件数を確認してください。CSV出力は条件やチェックに関係なく、保存済みの全機器が対象です。

運用環境への適用前には、実ブラウザーで複数選択と値別解除、ボタンのラベル・件数、キーボードでの候補移動・選択・閉鎖、フォーカスの復帰を人手で確認してください。狭い画面での候補一覧・チップの表示と、表示ビュー変更時のチェック解除、他条件変更時の表示外チェック保持も確認対象です。

「接続」では機器名・ラベル・ポート・VLAN・系統名を検索できます。系統のない接続は「未設定」で検索します。行本体はキャンバスの接続を選択し、チェックは一括設定の対象だけを変更します。「表示中をすべて選択」は検索結果の接続だけを追加します。非表示の選択件数も確認してください。

「一括設定」で系統・VLAN・ラベル・備考の変更項目をチェックします。OFFは現在値を保持し、ONの空欄は値を消します。系統の解除は「割り当て解除」を選びます。接続元・接続先・ポート・経路は変更しません。適用は現在ビューの1つの変更として自動保存します。競合時は変更内容を控え、既存の「競合したビューを再読込」で対応してください。

## バックアップと復元

- Web バックアップは `netarium-config` 形式 1 の構成情報 ZIP です。
  `manifest.json` と `data/netarium.json` だけを含み、ZIP 24 MiB 以下、展開後合計 64 MiB 以下、2 ファイルに制限します。
  構成情報と画像参照メタデータを保存し、画像実体は含めません。
  現行スキーマ 16 では、ラック、奥行き、棚板、フロア配置参照を含む 15 テーブルの構成データを保持します。
  スキーマとアプリ版の互換性は `BackupCompatibilityPolicy` で検証し、旧画像同梱形式 2〜7 は変換・復元できません。
- 復元処理は、同一メジャー内の順方向（source <= target）の正規 SemVer、および移行経路が存在するスキーマ 11〜16（11..16）を受け付けます。
  新版から旧版への逆方向復元は、同一スキーマであっても拒否します。
  スキーマ 11〜15 の旧バックアップから復元する場合は、元契約を厳密に検証した上で現行スキーマ 16 へ構成を順次変換・移行して取り込みます。
- Web 構成情報復元は構成全体の置換であるため、復元先のみに存在するビュー、機器、ラック配置などの情報は置き換わります。
  このデータ消失はプレビュー画面に明示し、復元前の自動バックアップによって退避します。
  利用者、パスワード、認証状態、全セッション、ディスク上の画像実体は変更しません。
  復元前の画面からの保存等は世代不一致で拒否されるため、画面を再読み込みしてください。
- サーバー管理者の停止型完全バックアップ（`scripts/restore-full.ps1`）では、隔離領域で元 DB を検証した後に通常更新と同じ `migrateDatabase()` を適用してスキーマ 16 へ移行し、再検証後に配置します。
  利用者、パスワード、初回変更状態、認証試行制限、bootstrap 状態、監査ログ、セッションは Web ZIP の対象外です。
  全損復旧（画像実体・利用者を含む）には、サーバー管理者用の停止型完全バックアップ CLI（`scripts/backup-full.ps1`／`scripts/restore-full.ps1`）を使用します。
- アプリケーション更新失敗時に更新前スナップショットから一括復帰するロールバックは、過去バックアップの復元とは独立した別操作として扱います。
- 機器台帳や図面を大幅に変更した際、定期保守時、およびプログラム・DB変更前に画面から手動でバックアップZIPを取得し、サーバー外の安全な保管領域（管理用端末やファイルサーバ）へ移して数世代を管理します。
- 月次等の定期保守に合わせて、本番と隔離された検証環境で復元試験を行います。

機器の設置場所（`location`）150文字、接続のVLAN（`vlan`）100文字までを通常保存と同じ上限で出力・復元します。上限超過のZIPは検証時に拒否し、現行データを置き換えません。接続のVLANは機器台帳CSVの対象外です。

復元ではビュー、機器（保守接続情報含む）、監視状態、配置、接続、系統と割当、メモ、照合済みの画像参照を置き換えます。プレビューで画像の一致・欠損・不一致件数と機器ID／ビューIDを確認してください。保存名・サイズ・MIME・寸法・SHA-256のすべてが一致する実体だけを参照し、欠損・不一致の参照は復元しません。元メタデータはZIPに残りますが、画像実体は作成・上書き・移動・削除・再変換せず、復元時の画像GCも行いません。

DB移行11で画像の`sha256`列を追加します。登録時は保存用変換後の実体をハッシュします。旧行でdigestがない場合、初回出力時に保存名・サイズ・MIME・寸法が一致する実体だけをハッシュして補完します。欠損・不一致の画像を自動修復する処理ではありません。

利用者・パスワードと全利用者のセッションは実行者を含め維持し、再ログインは不要です。復元前の画面からの保存等は世代不一致となるため、再読み込みしてください。復元中は更新操作、画像配信、別の復元をサーバー側で拒否します。形式・安全契約の正本は[運用ガイド（復元）](operations.md#復元)です。

復元プレビューの利用期限は、プレビュー成功時から600秒です。期限を過ぎた場合はZIPを再選択してプレビューをやり直します。失効した作業領域は、次のプレビュー開始、復元確定（commit）開始、またはサーバー管理者の清掃CLI実行時に回収されます。画面を閉じただけでは即時削除されず、常駐タイマーによる600秒後の削除も保証されません。

作業領域の既定保持上限は全体8件・4GiB、ユーザーごと2件・1GiBです。単体ZIP24MiB・展開後64MiBの上限超過はHTTP 400、保持上限超過はHTTP 413で業務DB・既存画像を変更する前に拒否します。有効トークンを容量確保のために削除しません。413が解消しない場合は管理者へ引き継ぎます。HTTP 409の処理競合は別処理の終了を待ち、現行データ変更による409は最新状態を確認してプレビューからやり直します。清掃と未実施の人受入は[運用ガイド](operations.md#復元プレビューの保持上限と回収197)を参照してください。

「後処理要対応」が表示された場合、DB復元は確定済みです。復元を繰り返さず、`data/logs/restore.log`と監査ログの調査ID、自動バックアップの整理やログ追記の状態を確認してください。復元の後処理で画像実体を削除することはありません。

復元前自動バックアップも同じ構成情報ZIPとして`data/backups/auto`へ保存します。画像・利用者の退避や長期保管用バックアップの代替にはならず、サーバ全損時には利用できません。容量確認ではDB、画像、バックアップ、一時領域、監査・IIS・PHPログを対象にします。PHP推奨設定は`upload_max_filesize=32M`／`post_max_size=34M`、IIS通常要求上限は32MiBとし、Web ZIPの24MiB上限や画像投稿専用31MiBと区別します。

## 定期保守

| 頻度 | 確認内容 |
|---|---|
| 日次または利用時 | ログイン、画面読み込み、保存エラー、Ping結果、ディスク空き容量 |
| 週次 | IIS・PHPログ、`data/logs/restore.log`、`data/logs/audit`の容量点検と`scripts/prune-audit-logs.php`実行、`data/temp`、復元作業領域の件数・容量と`scripts/prune-restore-previews.php`の終了コード、品質診断 |
| 月次または定期保守時 | サーバ外バックアップの確認、隔離された検証環境での復元試験、アカウント棚卸し、証明書期限、Windows/IIS/PHP更新情報 |

`data/db/csv-import`、`data/temp/backup-export`の一時データは通常10分で失効します。`data/temp/backup-restore`は上記の600秒の利用期限と回収契機に従い、定期保守では`php scripts/prune-restore-previews.php`を使います。必要ならサーバー管理者がWindowsタスクスケジューラへ登録しますが、アプリによる自動登録はありません。ロック競合の非ゼロ終了は次回へ回し、削除失敗はACLや使用中ファイルを調査します。肥大化時の手動整理は、利用者がいない保守時間帯にIISと処理中のFastCGI要求・清掃CLIを停止・終了確認してから行います。処理中のファイルと有効トークンの領域を削除せず、稼働中の`.workspace.lock`も削除しません。詳細は[運用ガイドの回収手順](operations.md#復元プレビューの保持上限と回収197)に従います。

## 障害時の初動

| 事象 | 最初に確認すること |
|---|---|
| サーバ全損（ハードウェア故障・OS破損等） | [運用ガイド](operations.md#サーバ全損からの再構築)に従い新規環境を構築し、外部保管された完全バックアップZIPから`scripts/restore-full.ps1`でDB・画像・利用者を一体復元 |
| 画面が読み込めない | IISサイトとアプリケーションプール、PHP FastCGI、IIS/PHP/Windowsログ、`data`権限、DB容量 |
| 保存できない | 画面エラー、他利用者の保存、リビジョン競合、`data/db`権限、ディスク空き容量 |
| 操作時に保守作業中（HTTP 404専用拒否）と表示される | サーバー保守作業中（`NETARIUM_MAINTENANCE_REJECTED`）。画面を再読み込みせず入力や図面設定を保持したまま待機し、保守終了後に上部「保存」ボタンで明示的に再開 |
| Pingできない | IPアドレス、サーバーからの手動Ping、`exec`、`ping.exe`実行権限、ICMP設定、プライベートIPv4条件 |
| 図面を表示できない | フロアビュー、`data/uploads/floorplans`権限、ファイルの手動移動有無、`floor_plan.php`の認証後応答 |
| 画像アップロード時にHTTP 413エラーとなる | アップロード要求が 31 MiB の上限を超過（IIS 413.1）。画像サイズを縮小して再試行。保守中は 404.7（専用 JSON 拒否）が優先 |
| バックアップ・復元できない | PHP ZIP拡張、`data/temp`・`data/backups`・`data/logs`権限、空き容量、アップロード上限、復元ログ |
| 操作時にHTTP 503エラーとなる | 別の保存処理によるSQLite書込み待ち、監査ログ保存先（`data/logs/audit`）の空き容量（256MiB上限）、ディレクトリおよび`.lock`のOS書込権限、PHPエラーログ。通常保存では「保存状態を確認」を先に実行し、再試行可能と判定された場合だけ再保存。新規作成を含む場合は最新データを再読み込み |

画面やエラー応答に調査ID（`request_id`）が表示されている場合は、サーバー上のPowerShellで `Get-Content <storage_dir>\logs\audit\audit-*.log | Select-String "<request_id>" | ForEach-Object { $_.Line | ConvertFrom-Json }` を実行することで、該当操作の監査行を抽出・確認できます。

障害対応中もDBを手動編集しないでください。画像実体が残る環境の構成復元には影響プレビューを確認した上でWeb構成情報ZIPを使用でき、画像・利用者を含む全損復旧にはサーバー側停止型完全バックアップ（`scripts/restore-full.ps1`）を使用します。

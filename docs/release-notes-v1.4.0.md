# Netarium v1.4.0 リリースノート

Netarium v1.4.0 では、機器への複数 IP アドレス登録、ネットワーク区分と IPv4 セグメントを管理する軽量 IPAM、重複 IP に対する Ping 到達性制御、機器・ビューの変更履歴、機器 Config の世代保管と差分比較など、日常のネットワーク運用と構成管理に対応する機能を追加しました。
また、利用者の論理削除・復元への対応、ブラウザ内利用ガイドの全面再構成、操作性の改善および不具合修正を実施しました。

## 主要機能

### 複数 IPv4 アドレス（追加 IP）の管理
- 機器ごとに複数の追加 IPv4 アドレス、用途ラベル、表示順を登録・編集・検索できます。
- 機器個票およびプロパティパネルで追加 IP を管理できます。機器台帳一覧では管理 IP 直後の「追加IP」列に件数を表示します。
- 台帳の CSV 入出力形式を、`ip` 列の直後に `additional_ips` 列を追加した固定 20 列形式へ拡張しました。旧 19 列形式の CSV は取り込めません。
- `additional_ips` は用途ラベルと順序を持つ JSON 配列です。空欄は既存値を保持し、`[]` は全削除、配列の指定は全置換として扱います。
- 同一機器内と同じネットワーク区分内の新規 IP 重複は拒否し、別区分の同値 IP は許容します。未分類の新規重複には、対象確認が必要です。

### ネットワーク区分と IPv4 セグメント管理（軽量 IPAM）
- 管理メニューに「IPアドレス管理」を追加しました。ネットワーク区分（アドレス空間）と IPv4 セグメントを階層管理できます。
- CIDR 入力時にサブネットマスク、ネットワークアドレス、ブロードキャストアドレス、ホスト範囲を即時プレビューします。
- ホスト用 IP 登録率（ホスト範囲内の一意な登録 IP 数／ホスト総数）を表示します。実ネットワークの使用率や空き率ではありません。/31・/32 は範囲内の全 IP をホストとして扱います。
- 台帳に登録された管理 IP・追加 IP は、CIDR 範囲に基づいてセグメントへ自動所属します。複数の候補がある場合や候補外の IP は「未分類」として管理し、個別または一括で再分類できます。
- 閲覧者は参照のみ、管理者は編集・削除・再分類を行えます。

### 重複 IP と Ping 到達性判定
- ネットワーク区分ごとに、Netarium サーバーからの到達性（未設定／到達可能／到達不可）を設定できます。
- Ping は管理 IP のみが対象です。他機器の管理 IP・追加 IP と重複する場合、対象が「到達可能」で他の同値登録すべてが「到達不可」の場合だけ実行します。複数の到達可能区分や未設定・未分類が混在する重複は、理由付きでスキップします。
- 未設定でも一意な管理 IP は従来どおり実行でき、到達不可区分の管理 IP は実行しません。この設定は OS の通信経路や Ping の既存の IP 制限を変更しません。
- データ品質診断に新警告（`ambiguous_ping_target`）を追加し、通信先を特定できない重複 IP を検出して該当セグメントの一覧へ誘導します。

### 機器・ビューの変更履歴
- 管理者専用機能として「変更履歴」を追加しました。
- 機器およびビュー（論理図・物理図・ラック搭載図）の主要な変更内容、変更前後の値、日時、操作者を横断確認できます。
- 期間（7日／30日／90日、最大 90 日保持）、対象種別、対象名、操作者による絞り込みに対応しています。
- 機器個票やビュー管理から直接履歴へ遷移できます。削除済み対象の履歴も 90 日間保持します。

### 機器 Config の手動保管と世代・差分管理
- 管理者が機器個票の「Config」から、設定テキストを手動で保管できます（UTF-8、最大 5 世代、1 版 256 KiB、システム全体 40 MiB）。
- 直近登録版と過去版を行単位で差分比較できます。差分内の本文検索や変更箇所（前／次）への移動に対応しています。
- 本文検索、全文・部分コピー、世代ごとの選択削除を行えます。

## 利用者向け改善と不具合修正

### 操作性・UI の改善
- **機器台帳の選択操作**: チェックボックス列のセル余白をクリックしても選択が反転するよう改善しました。
- **利用ガイドの再構成**: ブラウザ内利用ガイドをトップ＋機能別 4 ページ（構成図・機器台帳・ビューラック・保存管理）へ分割し、手順・箇条書き・表を中心とした操作ガイドへ刷新しました。最新 UI キャプチャへの更新と、旧 URL アンカーからの自動転送に対応しています。
- **機器個票の 2 タブ化**: 個票を「機器・設置・資産」「管理・保守・状態」の 2 タブに再構成し、画像枠の常設化（3 枠）や追加 IP 欄の整理を行いました。
- **機器のダブルクリック操作**: キャンバス上の機器をダブルクリックして機器個票を開けるようにしました。
- **最終表示ビューの復元**: 最後に表示したビュー ID をブラウザ内に保存し、再読み込み時や次回アクセス時に自動復元します。
- **管理モーダルの統一**: 操作・管理モーダルのヘッダーデザインを上端 32px 基準へ統一しました。

### 利用者管理
- 利用者管理に「削除」および「削除済み」タブを追加しました。
- 利用者を論理削除（`users.deleted_at`）し、即時にログイン不可化および既存セッションの失効を行います。
- 利用者 ID、ユーザー名、権限、監査履歴を保持したまま、削除済み一覧から無効状態で復元できます。自分自身および最後の有効な管理者の削除は防止します。

### 不具合修正・堅牢化
- 利用者の無効化または論理削除後、停止中に要求しなかった旧セッションが再開・復元時に復活する不備を修正しました（再開後は再認証が必要）。
- 保存・CSV 取込時に新たに生じる IP 重複のエラー・警告を合計最大 1,000 組に制限しました。超過時は対象操作全体をデータ変更なしで拒否して分割を案内し、CSV の警告振り分けも索引化しました。
- 停止型完全バックアップ復元時に、アドレス空間・セグメント・変更履歴の採番カウンタを検証し、不正なデータベースを配置前に拒否するよう強化しました。
- Config 本文の総量判定を UTF-8 実バイト数で行うよう修正し、上限超過時は保存前の状態へ確実にロールバックします。
- Config 差分計算では、共通前後行を除去してから計算量を判定し、長い本文の末尾 1 行変更などを比較できるようにしました。計算量と最大 4,000 描画行の上限は維持します。
- Web 構成情報 ZIP の復元処理において、管理 IP に対する IPv4 形式の検証を厳格に適用しました。

## アップデート手順（v1.3.0 からの更新）

Netarium v1.3.0（DB スキーマ 16）から v1.4.0 への更新では、データベーススキーマが自動的にスキーマ 22 へ移行されます。

### 1. 更新前の完全バックアップ取得
作業前に、停止型完全バックアップを取得し、外部へ保管してください。
- **Windows / IIS 環境**: 管理者 PowerShell で `scripts/backup-full.ps1` を実行します。
- **Docker 環境**: `bash scripts/docker-backup.sh` を実行します。

### 2. プログラムの更新
環境に応じた手順で更新を実施します。詳細な手順や前提条件は各ガイドを参照してください。
- **Windows / IIS 環境**:
  新バージョンの配布資材を展開し、管理者 PowerShell で `scripts/update.ps1` を実行します。詳細は [更新・ロールバックガイド](https://github.com/LGUG-jp/netarium/blob/v1.4.0/docs/update.md) を参照してください。
- **Docker 環境**:
  `compose.image.yaml` のイメージタグを `ghcr.io/lgug-jp/netarium:1.4.0` に変更し、`bash scripts/docker-update.sh -f compose.image.yaml` を実行します。事前完全バックアップ、DB 移行、起動確認と失敗時の切戻しを既存スクリプトで行います。詳細は [Docker 配備・運用ガイド](https://github.com/LGUG-jp/netarium/blob/v1.4.0/docs/deployment-docker.md#7-更新ロールバック手順) を参照してください。

### 3. DB スキーマの自動移行
更新後の初回起動時に、データベーススキーマが 16 から 22 へ自動的に移行されます。管理者が手動で SQL を実行する必要はありません。

## 互換性と運用の注意点

- **台帳 CSV フォーマットの変更**:
  旧バージョン（v1.3.0 以前）の 19 列形式の CSV は取り込めません。`ip` 列の直後に `additional_ips` 列を含む新 20 列形式を使用してください。機器台帳の「CSV出力」から最新フォーマットのテンプレートを取得できます。
- **IPAM の初期状態**:
  アップデート直後はネットワーク区分およびセグメントは未登録です。既存の登録済み IP はすべて「未分類」となり、Ping 到達性設定は「未設定（unset）」となります。必要に応じてネットワーク区分とセグメントを作成し、再分類を行ってください。
- **変更履歴の記録開始**:
  v1.4.0 より前の過去の変更操作は遡及生成されません。変更履歴は v1.4.0 への更新後に実行された操作から記録されます。
- **Config の秘密情報とバックアップ仕様**:
  - 登録前にパスワードや秘密鍵などを除去・マスクしてください。Config は暗号化保管機能ではなく、本文に残した秘密値は SQLite と両方式の ZIP に含まれます。ZIP は管理者限定とし、安全なサーバー外領域へ保管してください。
  - Web 画面から出力する「Web 構成情報バックアップ（`netarium-config`）」には、各機器の直近 1 世代のみが含まれます。Web 構成情報を復元した場合、バックアップに含まれない過去世代は保持されません。全世代（最大 5 世代）を保持するには、サーバー側の「停止型完全バックアップ（`netarium-full`）」を使用してください。
- **旧バージョンへの切り戻し（ロールバック）制約**:
  - 旧バージョン（v1.3.0 等）へ切り戻す場合は、更新直前の同じスナップショットからプログラム／Docker イメージ・DB・画像・環境設定を一括復元してください。DB のスキーマ番号だけを戻さないでください。
  - v1.4.0 で取得したバックアップ ZIP（Web 構成情報および停止型完全バックアップ）を、旧バージョンの Netarium へ復元することはできません（安全のため拒否されます）。
- **完全バックアップ ZIP の対象外データ**:
  停止型完全バックアップ ZIP には、環境設定ファイル（`config/app.php`、`.env` など）や Web サーバーログ、SSL/TLS 証明書等は含まれません。これらの設定・ログファイルはサーバー管理者側で別途保全を行ってください。

# Netarium v1.5.0 リリースノート

Netarium v1.5.0 では、フロア配置図の角度微調整（0.1° 単位の回転・数値入力）および不透明度の直接数値入力、機器個票からの機器直接削除、機器 Config 管理における前後機器への直接移動など、日々の構成図作成および機器台帳運用の操作性を向上させる機能追加を実施しました。
また、データベーススキーマを 23 へ移行し、旧バージョンバックアップからの安全な順方向復元に対応したほか、開発時の品質向上のための限定的な型チェックを導入しました。

## 主要機能

### フロア配置図の角度微調整（0.1° 回転）と不透明度の数値入力
- **0.1° 単位の回転調整**: 図面調整ツールバーに、左右の回転アイコンによる ±0.1° ずつの微調整ボタンと、小数第 1 位までの数値入力欄（−180.0〜180.0°）を追加しました。`0` を入力することで即座に水平復帰できます。
- **統一された描画と操作**: 回転後も中心基準で四隅ハンドル、ドラッグ移動、拡大縮小、全体表示、印刷プレビューが同一の座標系で正しく動作します。
- **不透明度の直接数値入力**: スライダー（25/50/75% 目盛り表示）に加え、10〜100% のパーセント数値を直接入力できる入力欄を追加しました。
- **ツールバーの折り返し対応**: 画面幅が狭い場合でもグループ単位で自然に折り返して表示されます。

### 機器個票からの機器直接削除
- 機器個票モーダル内に「この機器を完全削除」ボタンを追加しました。
- 機器台帳一覧に戻ることなく、個票を表示したまま対象機器を削除できます。
- 全ビューの配置・関連接続への影響確認ダイアログが表示され、未適用の入力や保存競合の保護を維持した上で安全に削除されます。

### 機器 Config 管理での前後機器切り替え
- 機器個票の Config 管理モーダル上部に「前へ」「次へ」ボタンを追加しました。
- 機器台帳一覧の現在の絞り込み・並び順を維持したまま、前後の機器へ直接移動して Config を閲覧・編集できます。
- 未保存の変更がある場合は破棄防止ガードが働き、誤った移動を防ぎます。

### 開発時限定の型チェック導入（保守性改善）
- フロントエンド開発時の型安全性向上と保守性検証のため、JSDoc 型注記と TypeScript（`tsc --noEmit`）による限定的な型チェックを一部モジュール（接続経路データ、手動接続経路、リソース保存契約）に導入しました。
- **本番環境への影響なし**: これは開発時の静的検証であり、**本番環境に TypeScript や Node.js ランタイムを一切要求しません**。ブラウザにはトランスパイル不要の標準 JavaScript がそのまま配信されます。
- 全面展開（`.ts` への移行や全モジュールへの一括展開）は予定しておらず、維持コストと効果を検証した限定導入に留めています。

## アップデート手順（v1.4.0 からの更新）

Netarium v1.4.0（DB スキーマ 22）から v1.5.0 への更新では、データベーススキーマが自動的にスキーマ 23 へ移行されます。

### 1. 更新前の完全バックアップ取得
作業前に、停止型完全バックアップを取得し、外部へ保管してください。
- **Windows / IIS 環境**: 管理者 PowerShell で `scripts/backup-full.ps1` を実行します。
- **Docker 環境**: `bash scripts/docker-backup.sh` を実行します。

### 2. プログラムの更新
環境に応じた手順で更新を実施します。詳細な手順や前提条件は各ガイドを参照してください。
- **Windows / IIS 環境**:
  新バージョンの配布資材を展開し、管理者 PowerShell で `scripts/update.ps1` を実行します。詳細は [更新・ロールバックガイド](https://github.com/LGUG-jp/netarium/blob/v1.5.0/docs/update.md) を参照してください。
- **Docker 環境**:
  `compose.image.yaml` のイメージタグを `ghcr.io/lgug-jp/netarium:1.5.0` に変更し、`bash scripts/docker-update.sh -f compose.image.yaml` を実行します。事前完全バックアップ、DB 移行、起動確認と失敗時の切戻しを既存スクリプトで行います。詳細は [Docker 配備・運用ガイド](https://github.com/LGUG-jp/netarium/blob/v1.5.0/docs/deployment-docker.md#7-更新ロールバック手順) を参照してください。

### 3. DB スキーマの自動移行
更新後の初回起動時に、データベーススキーマが 22 から 23 へ自動的に移行されます。管理者が手動で SQL を実行する必要はありません。

## 互換性と運用の注意点

- **DB スキーマ 23 と図面回転角の保存**:
  - `view_floor_plans` テーブルに `rotation` 列（REAL 型）が追加されます。
  - v1.4.0 以前のデータベースから移行された既存のフロア図面は、回転角 `0.0°`（水平）として初期化されます。
- **バックアップ復元互換性**:
  - **順方向復元（旧版 → v1.5.0）**:
    - 旧バージョン（v1.0.0〜v1.4.0、スキーマ 11〜22）で取得された「Web 構成情報バックアップ（`netarium-config` 形式 1）」および「停止型完全バックアップ（`netarium-full` 形式 1）」は、v1.5.0 環境へ正常に復元できます。復元時に図面の回転角は 0.0° として安全に補完されます。
  - **逆方向復元（新版 → 旧版）の禁止**:
    - v1.5.0（スキーマ 23）で取得したバックアップ ZIP を、v1.4.0 以前の Netarium 環境へ復元することはできません（安全のため前段検査で拒否されます）。
- **旧バージョンへの切り戻し（ロールバック）制約**:
  - v1.4.0 等へ切り戻す場合は、更新直前に取得したスナップショットからプログラム／Docker イメージ・DB・画像・環境設定を一括復元してください。DB のスキーマ番号だけを戻さないでください。
- **完全バックアップ ZIP の対象外データ**:
  - 停止型完全バックアップ ZIP には、環境設定ファイル（`config/app.php`、`.env` など）や Web サーバーログ、SSL/TLS 証明書等は含まれません。サーバー管理者側で別途保全を行ってください。

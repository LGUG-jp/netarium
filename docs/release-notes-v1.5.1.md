# Netarium v1.5.1 リリースノート

Netarium v1.5.1 は、接続モード中におけるキャンバス移動の操作性改善と、公開ドキュメントの整備を行うメンテナンスリリースです。
データベーススキーマ（23）およびバックアップ形式（形式 1）に変更はありません。

## 主な変更

### 機能改善：接続モード中の空白ドラッグによるキャンバス移動

- **接続モードのままパン移動が可能**：接続モード中にキャンバスの空白部分を左ドラッグ（Shift+ドラッグを含む）すると、表示倍率を変えずにキャンバスを移動できます。
- **接続状態の保持と安全制御**：接続元の選択状態、**接続元を固定**の ON／OFF、接続作業状態を保持したまま、離れた接続先をクリックして接続を作成できます。機器、フロア配置ラック、接続線、経路編集要素、キャンバスメモ、操作ボタンやツールバー上からはパンを開始せず、パン直後の誤クリックも抑止します。
- **利用ガイドへの反映**：ブラウザ内利用ガイド（`public/help-canvas.html`）の「接続の作成と削除」へ操作説明を追記しました。

### ドキュメント整備

- **スクリーンショットの掲載**：`README.md` に主要 UI 4 画面（メイン画面、フロア配置図、ラックビュー、機器個票）のスクリーンショットを掲載しました（公開リポジトリへは Docs-only 更新で先行反映済みです）。
- **コミュニティの位置付けと貢献規定の明確化**：`README.md` にコミュニティ **LGUG（Local Government Underground）** の活動位置付け（特定自治体の公式事業や公式提供製品ではなく、各導入組織の判断で利用する汎用ソフトウェアである旨）および `CONTRIBUTING.md` への導線を追記しました。あわせて `CONTRIBUTING.md` に、MIT License での提供権限確認、第三者素材や AI 生成物を含む権利・利用条件の尊重、権利帰属に疑義がある場合の保留方針、および外部貢献の取り込み・反映時の著作権・クレジット保持方針を整理しました。

## アップデート手順（v1.5.0 からの更新）

Netarium v1.5.0（DB スキーマ 23）から v1.5.1 への更新では DB スキーマ変更は発生しません。
v1.4.0（DB スキーマ 22）以前から更新する場合は、更新後の初回起動時にデータベーススキーマが 23 へ自動移行されます。

### 1. 更新前の完全バックアップ取得

作業前に、停止型完全バックアップを取得して外部へ保管してください。

- **Windows / IIS 環境**：管理者 PowerShell で `scripts/backup-full.ps1` を実行します。
- **Docker 環境**：`bash scripts/docker-backup.sh` を実行します。

### 2. プログラムの更新

環境に応じた手順で更新を実施します。

- **Windows / IIS 環境**：
  新バージョンの配布資材を展開し、管理者 PowerShell で `scripts/update.ps1` を実行します。手順と前提条件は [更新・ロールバックガイド](update.md) を参照してください。
- **Docker 環境**：
  ソースビルド構成では最新資材を取得して `bash scripts/docker-update.sh` を実行します。事前ビルド済みイメージ構成では、対象リリースの公開状況を GitHub Releases および GitHub Packages で確認した上で `compose.image.yaml` のイメージタグ（`ghcr.io/lgug-jp/netarium:1.5.1`）を指定し、`bash scripts/docker-update.sh -f compose.image.yaml` を実行します。手順は [Docker 配備・運用ガイド](deployment-docker.md#7-更新ロールバック手順) を参照してください。

## 互換性と運用の注意点

- **DB スキーマとバックアップ形式**：DB スキーマは `23`、バックアップ形式は Web 構成情報 ZIP（`netarium-config` 形式 1）および停止型完全バックアップ ZIP（`netarium-full` 形式 1）のまま変更ありません。
- **バックアップ復元互換性**：
  - **順方向復元（旧版 → v1.5.1）**：同一 MAJOR 内の過去正式版（`v1.0.0`〜`v1.5.0`、スキーマ 11〜23）で取得された両形式のバックアップ ZIP を v1.5.1 環境へ復元できます。
  - **逆方向復元（v1.5.1 → v1.5.0 以前）の拒否**：`BackupCompatibilityPolicy` により、v1.5.1 で取得したバックアップ ZIP は同一スキーマ 23 であっても v1.5.0 以前の環境へ復元できません（前段検査で拒否されます）。
- **旧バージョンへの切り戻し（ロールバック）制約**：v1.5.0 等へ切り戻す場合は、更新直前に取得したスナップショットからプログラムまたは Docker イメージ・DB・画像・環境設定を一括で復元してください。
- **完全バックアップ ZIP の対象外データ**：環境設定ファイル（`config/app.php`、`.env` など）、Web サーバーログ、SSL/TLS 証明書等は停止型完全バックアップ ZIP に含まれません。サーバー管理者側で別途保全してください。

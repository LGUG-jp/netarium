# Netarium

Netarium（ネタリウム）は、ネットワークの構成図と機器情報を一か所で整理・管理するための Web アプリケーションです。組織内のイントラネット環境において、構成図、機器台帳、IP アドレス、設置場所、接続、フロア図面、機器画像、保守情報、手動 Ping 結果を相互に関連付けて扱います。

単に見栄えの良い構成図を描いて終わりにせず、日々の運用確認、障害対応、担当者間の引き継ぎに使える実用的な情報資産として整理することを重視しています。

プロダクトコンセプト、名称の由来、ロゴの意図については [Netarium について](docs/about.md) を参照してください。画面設計や操作語彙の規律は [デザインガイドライン](docs/design-guidelines.md) にまとめています。

## バージョン

現在のバージョンは 1.1.0 です。変更履歴は [CHANGELOG.md](CHANGELOG.md) を参照してください。

## 主な機能

- ネットワーク機器台帳の登録、編集、検索、7項目（表示ビュー・施設・フロア・状態・種別・IP登録・配置状態）の複数選択による絞り込み（項目内OR、項目間・検索AND、0選択はすべて）、値別チップ解除・条件の全解除、選択機器の11項目の一括編集
- 機器単位・ビュー単位の競合検知による複数人編集（操作確定時の自動保存）
- 論理構成図とフロア配置図の作成
- 機器間の接続、ポート、VLAN情報の管理、共有区間の重なりを軽減する直交経路の自動算出、交差の山形ブリッジ／透過切れ目のブラウザー別表示設定と選択・hover時の経路強調
- 左「接続」の補助パネルとキャンバス操作による接続作成、接続元の固定による連続作成、接続一覧への移動（管理者のみ作成可能）
- 選択した接続の手動経路調整（水平・垂直区間のドラッグ、最大8折れの追加・削除、自動経路への復帰）と機器移動・寸法変更時の端点追従
- 全ビュー共通の接続系統（名称・8色パレット）と、系統色を保つ選択・hover・印刷
- 左「一覧」の機器／接続タブ、現在ビューの機器に絞った台帳への移動、系統名を含む接続検索、チェック選択による系統・VLAN・ラベル・備考の一括設定
- キャンバス上のメモ配置・本文編集・移動・サイズ変更と、共通ツールバーからの背景色・文字色の選択（各8色の色付き四角のプルダウン）、透明度・文字サイズの変更
- 通常キャンバスを変更しない印刷設定・専用プレビュー（全体／現在範囲、8機器種別、接続・図面・メモ・IP・ラベル・タイトル、縦横の選択、閲覧者利用、ブラウザーから紙／PDF出力）
- 機器の管理接続先（HTTP/HTTPS/SSH・ポート）と保守情報（担当部署・保守ベンダー・導入年月・保守期限）の管理
- 機器画像（1機器最大3枚、EXIFメタデータ除去、向き補正後に長辺2,048px以下へ縮小、原本保存なし）の登録、認証配信、拡大表示と前後の画像切替
- PNGまたはJPEGのフロア図面登録（入力30MiB・各辺7,000px・3,500万画素以下、向き補正後に長辺4,096px以下へ自動縮小、原本非保持、ビュー管理からの直接起動に対応）
- Windows の `ping.exe` または Docker 内の Linux `ping` を使用した管理者による手動疎通確認（台帳のチェック選択、NG絞り込み後の再実行、現在ビューの選択機器）と、結果モーダルでの絞り込み・全件CSVダウンロード
- 機器台帳の保存済み全件のCSV出力（絞り込み・チェック選択に依存しない）、検証付きCSV取込（新19列形式）
- データ品質診断とダッシュボード
- 構成情報 ZIP（`netarium-config` 形式 1／DB スキーマ 11）の出力・復元。画像は参照メタデータだけを含み、既存実体との一致をプレビューで確認します。画像実体・アカウント・パスワードは対象外、旧画像同梱形式 2〜7 は非対応です
- 管理者と閲覧者の権限制御
- 利用者の登録・停止・再開・権限変更、パスワード変更・再設定
- 7枚の操作キャプチャと2点のフロー図、小見出し付きの追従目次、キーボードでの画像拡大に対応したブラウザ内利用ガイド、共通Ping結果ミニヘルプ

Netarium は常時監視製品ではありません。Ping 機能は、画面から明示的に実行する疎通確認機能です。

## システム構成

- Web サーバー: IIS または Apache（Docker コンテナ）
- DocumentRoot: `public/`（Docker コンテナ内: `/var/www/html/public`）
- 実行環境: PHP 8.5.5以上（Windows IIS FastCGI）。Docker は `php:8.5-apache` ベースのイメージを使用
- データベース: SQLite Library 3.51.3以上（Docker イメージには SQLite 3.54.1 を組込み）
- フロントエンド: HTML、CSS、Vanilla JavaScript
- 標準タイムゾーン: Asia/Tokyo

必要な PHP 拡張は `PDO`、`pdo_sqlite`、`sqlite3`、`fileinfo`、`zip`、`session`、`json`、`gd`、`exif`、`mbstring` です。`mbstring` は台帳文字列のコードポイント制限と CSV 取込に必須です。日本語処理のため、任意の推奨拡張 `intl` も有効化してください。

## ディレクトリ

```text
netarium/
├─ public/                  IISが公開するPHP、CSS、JavaScript、画像
├─ src/                     PHP実装
├─ templates/               PHPテンプレート
├─ config/app.example.php   配備設定の例
├─ config/app.php           環境固有設定（Git管理外）
├─ data/                    実行時データ（Git管理外、Web非公開）
│  ├─ db/data.sqlite
│  ├─ uploads/floorplans/
│  ├─ uploads/device_images/
│  ├─ logs/
│  └─ temp/
├─ scripts/                 配備、更新、復旧、検証スクリプト
├─ tests/                   回帰テスト
└─ docs/                    開発・運用文書
```

`scripts/` 内の各スクリプトの用途、実行区分（管理者用入口／内部部品／開発・検証用）、詳細ガイドへの対応は [スクリプト一覧](scripts/README.md) を参照してください。

`data/`は配備先の環境固有領域です。`config/app.php`も環境固有ファイルで、`config/app.example.php`だけをリリースへ含めます。機密情報や環境固有設定の取り扱いは[開発ガイド](docs/development.md)および[セキュリティポリシー](SECURITY.md)に従います。

認証・セッションの共通処理は `src/Services/Auth/`、DB 接続・初期化は `src/Core/Database.php`、スキーマ 11 までの移行と初期ビュー生成は `src/Core/DatabaseSchema.php` に配置します。ルートの `auth.php` と `database.php` は使用しません。処理境界の正本は [アーキテクチャ](docs/architecture.md)、Web ZIP の形式・画像照合・互換性の詳細は [運用ガイド](docs/operations.md) および [手動配備・全損復旧ガイド](docs/deployment-manual.md) を参照してください。

## 入手方法

Netarium は GitHub 標準のソースコード配布形式で提供されます。利用環境に応じて次のいずれかの方法で取得してください。

1. **Git Clone**:
   ```bash
   git clone https://github.com/LGUG-jp/netarium.git
   ```
2. **GitHub Web からの ZIP ダウンロード**:
   リポジトリページの「Code」ボタンより「Download ZIP」を選択して取得します。
3. **GitHub Releases（公開後のリリース版）**:
   GitHub Releases が作成・公開されている場合は、配布される Source code (zip / tar.gz) を取得します。
4. **Docker コンテナイメージ（GitHub Container Registry）**:
   事前ビルド済みのコンテナイメージ（linux/amd64）を GHCR より取得して利用できます。
   ```bash
   docker compose -f compose.image.yaml pull web
   ```
   ※ 公開版の固定タグは `ghcr.io/lgug-jp/netarium:1.1.0` です。未公開候補の段階や開発環境ではローカルビルド（`compose.yaml`）を利用してください。


※ ソース配布にはテストコード（`tests/`）や開発用設定が含まれます。本番環境への配備手順は [クイックスタートガイド](docs/quickstart.md) または [配備ガイド](docs/deployment.md) を参照してください。

## クイックスタート

サーバー管理者が行う基本的な5つの運用操作の概要です。最短の手順、実行コマンド例、確認方法、注意事項は[クイックスタートガイド](docs/quickstart.md)を参照してください。

1. **インストール**: Windows Server + IIS + PHP 環境へ新規配備し、サービスを開始します（対話式セットアップスクリプトを用意）。
2. **アップデート**: 既存データや設定を保持したまま、新しいリリース版へプログラムを安全に更新します。
3. **バックアップ**: 障害や全損に備え、DB全体・画像実体・ユーザー情報を含む完全バックアップZIPを作成・退避します。
4. **リストア**: 完全バックアップZIPからDB、画像実体、ユーザー情報を既存環境または新規環境へ一括復元します。
5. **アンインストール**: IIS Site、Application Pool、プログラムを安全に撤去します（通常はデータ・設定を保持）。

※ バックアップ・リストアには、Web 画面から行う「Web 構成情報バックアップ（メタデータのみ）」と、サーバー管理者が CLI で行う「サーバー完全バックアップ（全損復旧対応）」の 2 系統があります。
※ 各操作の詳細や手動手順は、[配備ガイド](docs/deployment.md)、[更新ガイド](docs/update.md)、[運用ガイド](docs/operations.md)、[手動配備・全損復旧ガイド](docs/deployment-manual.md) を参照してください。
## セキュリティ上の前提

- インターネットに到達可能な本番環境ではHTTPSを必須とし、直接公開は避けてください。
- HTTPは[配備ガイドの許容条件](docs/deployment.md#http運用の許容条件と記録202)を管理者が記録・承認した閉域・隔離環境だけで使用してください。CSPやCookie属性は通信の暗号化を提供しません。
- 接続元を庁内・社内の許可された端末・ネットワークへ制限してください。
- `data/`、`src/`、`templates/`、`config/`、`scripts/`をHTTPで公開しないでください。
- 図面は認証付き`public/floor_plan.php`から配信し、`data/uploads/floorplans`を直接配信しないでください。
- 機密情報や環境固有設定の保護は[配備ガイド](docs/deployment.md)および[セキュリティポリシー](SECURITY.md)に従って管理してください。
- 新規パスワードの拒否リストは標準 PWDB 3,000 件を同梱し、固定 SHA-256 と両 MIT 表示を検証します。任意追加辞書は未設定でも動作し、管理者が非公開領域へ CLI 登録できます。設定後の欠損・改変は新規設定を拒否します。[辞書の運用手順](docs/operations.md#任意追加辞書)を参照してください。
- 診断用APIと詳細エラー表示は通常無効のまま使用してください。

脆弱性の報告方法は[セキュリティポリシー](SECURITY.md)を参照してください。
